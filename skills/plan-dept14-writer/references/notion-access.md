# Notion 存取（企劃一＋四部）

`plan-dept14-writer` 與 `plan-doc-qa` 共用。引用寫「見 `notion-access.md`」。

**金鑰自己去拿，不要問使用者。** 照下面的位置讀檔取值即可；讀不到才回報。

**一律走部門金鑰＋REST API。** 不要用個人帳號的 Notion MCP——那綁的是特定帳號，可見範圍與部門金鑰不同，會出現「某個人讀得到、其他人讀不到」的落差，而且**組員本來就沒有那個 MCP**，靠它寫出來的流程在別人機器上跑不動。

---

## 1. 唯讀金鑰（讀企劃頁、讀範本庫）

與企劃範本庫同一處：`X:\grp.product.pm1\2. 產品改造\一四部企劃範本`
（X 槽讀不到——在家／VPN 磁碟代號不同——換 `Y:\` 同路徑再試）

| 產品線 | 部別 | 取這支 |
|---|---|---|
| 神幣 | 一部 | 範本庫根目錄 `一部readonly_token.txt` |
| 娛樂城、鬥地主、魚樂園 | 四部 | 範本庫根目錄 `四部readonly_token.txt` |

**機台（老虎機、捕魚機等）＝娛樂城線＝四部。** 標題只寫「XXX 機台」「機台廣宣」的一律走四部，不要因為版位在神幣大廳、或文案提到神幣就判成一部——那是幣別與版位，不是產品線。

流程：判斷產品線 → 對應部別 → 讀該 txt 取值 → 以環境變數傳入呼叫 → 用完不留痕。

真的判不出來才兩支都試（讀不到只會回 404，沒有副作用）。

**頁面內容不只在文字層**：企劃的文案與排版常常整段放在**圖片**裡（排版示意、現有廣宣參考）。用 API 讀完 block 後，把 `image` 區塊的 URL 一併下載下來看圖，不要只讀到文字就以為讀完了。

## 2. 讀寫金鑰（回寫企劃頁）

各產品線一支，放在該線資料夾內：

| 產品線 | 部別 | 取這支 |
|---|---|---|
| 神幣 | 一部 | `神幣(一部)\一部readwrite_token.txt` |
| 娛樂城（含機台） | 四部 | `娛樂城(四部)\娛樂城readwrite_token.txt` |
| 鬥地主 | 四部 | `鬥地主(四部)\鬥地主readwrite_token.txt` |
| 魚樂園 | 四部 | `魚樂園(四部)\魚樂園readwrite_token.txt` |

### 前置：頁面必須先存在

**API 建不出範本頁**——「新增調整紀錄」按鈕是 Notion button block（API 不支援建立），資料庫範本（template）也無法用 API 套用。所以流程固定是：

```
PM 用部門範本「建立複本」→ 把頁面網址貼給 Claude → Claude 回寫中間章節
```

企劃頁是**資料庫項目**（parent 為 database），標題行屬性（類別／上線日期／網頁 ETA／負責 PM／工單等）由 PM 自己維護，**回寫內文不要去動屬性**。

### 護欄（回寫前必讀，五條都要做到）

1. **只寫 PM 自己建的那份複本頁**，不得改別人的既有企劃頁
2. 回寫前**先列出要改哪些區塊並取得同意**（見 SKILL.md 八.9）
3. 回寫後**一律回讀驗證**（讀回 block 比對，不是看畫面說好了）

   **2026-09-23 實測（直接餵 block JSON 走 REST API）**：heading、紅字待補值、**灰底＋刪除線**（廢除標記）、**綠底**（`YYYY/MM/DD vN.N調整為→`）、表格、mermaid 程式碼區塊、callout **回讀比對全部無損**；三層巢狀編號的**結構**也正確寫入。
   關鍵在**用 block JSON 的 `annotations` 直接指定**（`color: "gray_background"`、`strikethrough: true`），不要先轉成 Markdown 再請對方解析——走 Markdown 轉換那條路才會掉格式。
   ⚠️ **巢狀編號的顯示樣式驗不了**：API 不回傳 `list_format`，所以「是否顯示成 1.→a.→i.」只能靠人眼看頁面。已知 API 寫入的巢狀編號可能一律顯示 1.→1.→1.，需要 PM 在頁面手動調樣式——交付時主動告知這句。
   仍要回讀的原因：沒測過的排版（欄位版面、同步區塊、資料庫內嵌）不保證，寫錯了早點發現。
4. **經手人會變成 bot**：實測 API 回寫後頁面的 `last_edited_by` 會變成該線的 writer bot（`pm4_casino_writer` 這類），**不是操作的人**，而且會蓋掉原本的真人編輯痕跡。所以調整紀錄一定要寫明實際操作人：`YYYY/MM/DD vN.N 調整為→ …（經手：<人名>）`
5. 版本可還原：API 的編輯和人工編輯一樣會進 Notion 頁面編輯紀錄，改壞了可以從 `⋯` → 更新紀錄還原（保留天數依 workspace 方案）

## 3. 使用紀律（必守）

- token **只走環境變數**（如 `NOTION_KEY`）傳入，**不得寫進腳本、設定檔、文件或 commit 訊息**；試過的腳本存檔前把值抹成 placeholder
- token 值本身**不得複製到任何有遠端的 repo**，也不要貼進對話紀錄或 Slack
- REST API 呼叫固定帶版本標頭 `Notion-Version: 2022-06-28`
- 本檔只記**位置**，不記金鑰值，也不記申請／產生 token 的操作網址

## 4. 讀不到時怎麼辦

| 狀況 | 處理 |
|---|---|
| X:／Y: 都讀不到 | 多半是沒連內網／VPN。回報一句請使用者確認網芳連線，**不要改用猜的內容繼續做** |
| 有金鑰但頁面 404／無權限 | 該頁沒分享給 integration，或不在同一個 workspace。請 PM 分享頁面或貼出內容 |
| 只有唯讀卻被要求回寫 | 見 §2，輸出可貼上的片段，不要硬試 |
