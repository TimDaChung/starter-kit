# Notion 存取（企劃一＋四部）

`plan-dept14-writer` 與 `plan-doc-qa` 共用。引用寫「見 `notion-access.md`」。

**金鑰自己去拿，不要問使用者。** 照下面的位置讀檔取值即可；讀不到才回報。

**一律走部門金鑰＋REST API。** 不要用個人帳號的 Notion MCP——那綁的是特定帳號，可見範圍與部門金鑰不同，會出現「某個人讀得到、其他人讀不到」的落差，而且**組員本來就沒有那個 MCP**，靠它寫出來的流程在別人機器上跑不動。

---

## 1. 唯讀金鑰（讀企劃頁、讀範本庫）

與企劃範本庫同一處：`X:\grp.product.pm1\2. 產品改造\一四部企劃範本`
（X 槽讀不到——在家／VPN 磁碟代號不同——換 `Y:\` 同路徑再試）

| 產品線 | 部別 | 取這支 |
|---|---|---|
| 神幣 | 一部 | 範本庫根目錄 `一部readonly_token.txt` |
| 娛樂城、鬥地主、魚樂園 | 四部 | 範本庫根目錄 `四部readonly_token.txt` |

**機台（老虎機、捕魚機等）＝娛樂城線＝四部。** 標題只寫「XXX 機台」「機台廣宣」的一律走四部，不要因為版位在神幣大廳、或文案提到神幣就判成一部——那是幣別與版位，不是產品線。

流程：判斷產品線 → 對應部別 → 讀該 txt 取值 → 以環境變數傳入呼叫 → 用完不留痕。

真的判不出來才兩支都試（讀不到只會回 404，沒有副作用）。

**頁面內容不只在文字層**：企劃的文案與排版常常整段放在**圖片**裡（排版示意、現有廣宣參考）。用 API 讀完 block 後，把 `image` 區塊的 URL 一併下載下來看圖，不要只讀到文字就以為讀完了。

## 2. 讀寫金鑰（回寫企劃頁）

**不發放，只有主任持有。** 手上只有唯讀金鑰時不要嘗試回寫，也不要去翻其他資料夾找：

- `plan-doc-qa` 的「要我直接幫你改嗎」→ 改成輸出**可直接貼上的修正片段**交 PM 自行更新
- `plan-dept14-writer` 的交付 → 維持本地 Markdown，由 PM 貼上
- 真的需要系統回寫 → 把頁面與內容交主任處理

## 3. 使用紀律（必守）

- token **只走環境變數**（如 `NOTION_KEY`）傳入，**不得寫進腳本、設定檔、文件或 commit 訊息**；試過的腳本存檔前把值抹成 placeholder
- token 值本身**不得複製到任何有遠端的 repo**，也不要貼進對話紀錄或 Slack
- REST API 呼叫固定帶版本標頭 `Notion-Version: 2022-06-28`
- 本檔只記**位置**，不記金鑰值，也不記申請／產生 token 的操作網址

## 4. 讀不到時怎麼辦

| 狀況 | 處理 |
|---|---|
| X:／Y: 都讀不到 | 多半是沒連內網／VPN。回報一句請使用者確認網芳連線，**不要改用猜的內容繼續做** |
| 有金鑰但頁面 404／無權限 | 該頁沒分享給 integration，或不在同一個 workspace。請 PM 分享頁面或貼出內容 |
| 只有唯讀卻被要求回寫 | 見 §2，輸出可貼上的片段，不要硬試 |
