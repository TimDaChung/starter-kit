# 配件產圖提示詞模板

> 改提示詞只改這個檔。
> **先讀 `cannon-wing/prompt模板.md` 的「為什麼這樣寫」前科區**——那些教訓（注意力零和、特效偏黃綠、平台偶發異常）在這裡完全適用，不重複寫。

---

## 最重要的手法：用炮台翅膀定稿當參考圖

配件的風格必須衍生自定稿。**把定稿的 3×3 總覽圖（或裁切出的 lv0 炮台那格）當 `--reference` 餵進去**，比在提示詞裡用文字描述風格可靠得多：

```sh
python3 ~/.claude/skills/image-studio/scripts/image-studio-client.py draw \
  --count 2 --prompt-file <prompt.txt> --reference <定稿圖.jpg> --output <輸出目錄>
```

文字只負責講「畫什麼」，風格交給參考圖。這樣提示詞能保持短，不必花篇幅描述配色與材質。

---

## 通用開頭（各批共用，接在批次段落前）

```
你是一位遊戲美術設計師。請依照美術企劃，繪製捕魚機遊戲的炮台配件素材。

共同要求：
a. 這是遊戲內資產素材（非場景插畫），部件輪廓清晰可讀。
b. 風格、配色與材質必須與參考圖的炮台翅膀一致，這是同一套裝的配件。
c. 精緻度達到高營收商業手遊水準：材質要有明確高光與暗部層次，不可平塗；外緣有一圈外發光（rim light），確保能從深色海底背景中跳出。
d. 配色只用【填入企劃配色】。特效不可畫成螢光綠或黃綠色。
e. 畫面乾淨：沒有文字、標籤、數字、邊框、圓形或橢圓形底色卡。
```

## 批 1：子彈 ＋ 一般彈紋 ＋ 專屬彈紋

```
【通用開頭】

美術企劃：
- 子彈：【企劃 2.3.A 的概念與描述】
- 一般彈紋：【企劃 2.4.A 的概念與描述】
- 專屬彈紋：【企劃 2.4.B 的概念與描述】

輸出規格：
一張直式的圖，上下分區、背景單一純色。

- 畫面下半部中央：子彈。**直立、前端朝向畫面正上方**，尾焰或軌跡向下方拖曳。
- 畫面上半部：兩個彈紋左右並排。左邊＝一般彈紋，右邊＝專屬彈紋。

★ 彈紋一律畫成「正面、正圓」：中間的圖騰正立朝上，外框是標準的正圓形，不要壓扁成橢圓、也不要傾斜。

★ 兩個彈紋的整體尺寸要「一模一樣大」。專屬彈紋不是把一般彈紋放大或加粗，而是同樣大小、中間換了內容、細節更精緻的另一個版本。

三件之間留出明顯的空白間隔，不要重疊。
```

**出圖後必須跑轉向**，直式生成的版型要順時針轉 90° 才是交付版型：

```sh
python3 ~/.claude/skills/cannon-parts/scripts/rotate.py <素材.png> <轉向後.png>
```

**沒有專屬彈紋時**（企劃無 `2.4.B`）：刪掉專屬彈紋那兩行，彈紋只畫一個，置於上半部中央。

## 批 2：專屬獎圈

```
【通用開頭】

美術企劃：【企劃 2.4.C 的概念與描述，四個部位照抄】

輸出規格：
一張圖，畫面中央是一個獨立的獎圈，左右嚴格對稱，背景單一純色。

★ 最重要：獎圈的正中央必須是「空的」——中間留出一塊乾淨的圓形空間，不要畫任何東西進去，也不要用不透明的盤面把它填滿。這個圈是要套在別的東西外面用的，中央會顯示遊戲內容。企劃若寫「中心為某某底盤」，那只能是很淡的半透明襯底，不可遮擋。

環體與四周裝飾照企劃：外框材質與紋樣、兩側外張的裝飾、頂部冠飾、下方基座與寶石、外圍飄散的主題元素。
```

## 批 3：雷射子彈 ＋ 雷射彈紋（同一張）

參考圖餵兩張：炮台翅膀定稿＋批 1 成品（見 `配件規格.md` 批 3）。**不加 `--remove-background`**。

```
【通用開頭】

第二張參考圖是這套的一般子彈與一般彈紋，雷射版要跟它們是同一家族。

美術企劃：
- 雷射子彈：【套裝企劃「雷射特效 - 子彈」的描述】
- 雷射彈紋：【套裝企劃「雷射特效 - 彈紋」的描述】

輸出規格：
一張直式的圖，上下分區，背景單一純色的中性灰。

- 畫面上半部中央：雷射彈紋。完整的圓環狀爆裂光效，左右對稱。延續第二張參考圖裡的一般彈紋（中心圖騰、環體結構），但元素精簡、細節收斂——它在遊戲裡會持續顯示，畫得太複雜會干擾畫面。
- 畫面下半部中央：雷射子彈。延續第二張參考圖裡的一般子彈，整體拉長成光束，**直立、前端朝向畫面正上方**。
  只有前端有尖頭或圓頭的設計；末端就是光束本身，向下延伸出畫面或自然漸淡，**尾巴不要加第二個裝飾頭**。

兩件之間留出明顯的空白間隔，不要重疊。
```

## 實測前科

> 跨 skill 的通則（注意力零和、模型的固定偏誤、平台偶發異常）寫在 `kit 根目錄/references/image-studio-共用須知.md`，那邊才是權威。以下只記**本 skill 特有**的案例。

- **方向與尺寸要壓住，就會犧牲配色——注意力零和在這裡同樣成立。**
  批 1 第一版沒寫方向，配色乾淨、只有特效偏黃綠；加上「彈紋轉 90° 朝右」與「兩個彈紋等大」的強調句之後，方向與尺寸都修對了，但**整張圖連主體都染成黃綠**。
  **正確的取捨是：方向、尺寸這類「錯了就不能用」的結構性規格優先寫死，配色交給後製。** 不要試圖在提示詞裡同時壓住兩者。

- **`recolor.py` 的容錯範圍比想像中大。**
  上述那張有 46.1% 的像素落在黃綠色帶，位移後整體轉金，而白羽毛、藍寶石、藍色琴弦全部保持原色。只要色相帶不重疊，即使「主體本身」被染色也救得回來，不是只能修小面積特效。

- **轉向要描述「轉完長什麼樣」，不能只說「轉 90 度」。**
  有效的寫法是「豎琴的頂端要朝畫面右方，不可以畫成正立向上的」。這與 `cannon-wing` 處理喵公爵俯視倒轉臉時的教訓相同——只給角度沒用，要給結果的樣貌。

- **要求「換內容」時，直接給一個替代方案。**
  只寫「專屬彈紋要換中間的內容」，模型多半還是畫同一個圖騰再加光芒（變相的放大強化）。在企劃段就寫明「豎琴改為交疊的金色音叉與星芒」，一次就到位。

## 檢查

出圖後對照 `配件規格.md` 各批的驗收項目。最容易錯的三個：

1. **子彈朝向**——必須朝右，不是朝上或朝左
2. **獎圈中央被填滿**——這是最常見的錯誤，模型傾向把圓心畫滿
3. **交付格式搞混**——批 1／2 是去背 PNG（算圖要加 `--remove-background`），批 3 是灰底（**不要加**）
