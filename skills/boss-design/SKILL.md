# Boss 外觀設計 Skill

> **執行角色：美術企劃（兼玩法企劃視角）**——關注包裝、表演、玩法與外觀是否互相扣住、Boss 外觀是否忠實還原企劃、在漁場裡是否一眼認得出來、多階段差異是否明顯、造型是否 Spine 動得起來；交付前逐條跑驗收清單，不合格就重抽或改提示詞。

依賴同資料夾的檔案：

- `boss設計法則.md` — 畫面規格、外觀原則、Spine 限制（`boss-demo` 也引用）、驗收清單（硬規範）
- `prompt模板.md` — 外觀的提示詞模板、畫風錨點（改提示詞只改這份）
- `參考素材索引.md` — 既有 Boss 清單（撞題檢查）、畫風、已知企劃問題
- `scripts/fit_canvas.py` — 把算出的圖補成精準 16:9 灰底（`--cover` 裁切填滿模式給 `boss-scene` 用；`--transparent` 鍵掉灰底輸出透明 PNG）

共用的：

- **`kit 根目錄/references/生圖線共用流程.md`** — 魚線十支共用的工作流程：前置需求、讀企劃（`fetch_plan.py` 全 kit 唯一一份在 `art-request-sheet/scripts/`，`--list bosses` 列候選）、全程規則、從零發想的提案與拍板、挑圖、檢視與交付、接續下游。本檔只寫 Boss 線獨有的差異
- **`kit 根目錄/references/image-studio-共用須知.md`** — 算圖中斷、憑證到期、平台偶發異常、注意力零和。**遇到產圖層面的問題先查那份**

---

## 這支 skill 的定位

**產出的是 Boss 外觀的方向稿**，給美術畫正式的 2D Spine 素材。

| 歸這支 | 不歸這支 |
|---|---|
| Boss 外觀定稿圖（每階段一張） | Boss 專屬背景、表演場景 → `boss-scene` |
| | 捕獲／彩金表演、分鏡圖 → `boss-demo`（定稿後從 demo 截） |
| | 登場橫幅、彩金欄、結算欄、ICON → UI |
| | Spine 分件、骨架、動畫規格 → 不寫 |

**全部產出都是 16:9 灰底。**

## 全程規則

共用規則照 `生圖線共用流程.md` 第三節。本 skill 另加：

- **法則優先**：產圖前後都對照 `boss設計法則.md`，交付前逐條跑第六節驗收清單

## 三種模式

| 模式 | 觸發 | 起點 |
|---|---|---|
| **A 既有企劃** | 使用者指定 Boss 名，或給 Notion 連結 | Step 1 |
| **B 從零發想** | 使用者只給主題方向，或完全沒給 | Step B1 |
| **C 已有規格／提案文件** | 使用者自己已寫好主題、造型、玩法（md、docx、簡報、貼文），還沒進魚類之書 | Step C1 |

**拍板依據**：A 以企劃為準、C 以使用者的文件為準（確認一次造型條目即可）；**只有 B 必須提案拍板**。C 不出 2–3 案——使用者已經想好了，再提案是多一輪沒用的來回。

模式 B、C 確認後接回 **Step 3**；Step 3 之後三模式共用。

## 包裝、表演、玩法：外觀之前先談

**Boss 的外觀要服務包裝、表演與玩法**，三者沒定就先畫外觀，畫出來的招牌部位常常用不上。例：賽特的權杖是「閃電打罐子」的動作來源；幻狐的嘴與火是「吃幻石」的動作來源。

| 面向 | 要談的 | 既有企劃的例子 |
|---|---|---|
| **包裝** | 題材的賣點、活動檔期與定位、名稱、一句話宣傳 | 年獸＝新年檔期；劍魔＝共鬥副本 |
| **表演** | 被捕獲的反應、彩金表演的媒介與高潮、各獎級靠什麼拉開張力 | 賽特：舉杖放電 → 打罐子；墨海：憤怒膨脹 → 噴墨 |
| **玩法** | 彩金玩法的機制（打／抽／轉／選）、階段與翻盤、玩家有沒有操作 | 幻狐：抽幻石 4 輪＋翻盤；年獸：選路線（鬼腳圖）；劍魔：老虎機＋大轉盤 |

- **企劃有寫的一律照企劃**，不重新發想
- **企劃沒寫、或寫得不完整的面向，跟使用者討論**：提 2–3 個方案附理由，使用者拍板後寫進 mini 企劃（模式 A 則列成「企劃缺漏建議」，**不改企劃本身**）
- 這裡只談到**概念層級**（機制、媒介、高潮是什麼）；賠率、權重、秒數交給 `boss-demo`
- 玩法裡的道具（罐子、幻石、爆竹…）確定後，交給 `boss-props` 出等級系列圖

## 模式 B：從零發想

通則（提案與拍板不可跳過、B1 全部可選、B2 重撈清單、B3 2–3 案＋設計理由、B4 mini 企劃存檔與法則檢查、B5 重出整份）照 `生圖線共用流程.md` 第四節；A／C 以企劃或使用者文件為拍板依據，不走這段；只有 B 必須提案拍板。本 skill 的差異如下。

### Step B1 — 收集方向

問使用者：

1. **主題傾向**（例：神話神祇、東方神獸、深海霸主、節慶）
2. **定位**：活動 Boss／場景 Boss
3. **階段數**（1–3 階）
4. **畫風錨點**：指定一隻既有 Boss 的畫風，或不指定（見 `prompt模板.md` 第二節）
5. **包裝、表演、玩法**有沒有想法（例：「想要轉盤」「新年檔期」）——有就當提案的前提，沒有就由提案發想

### Step B2 — 避開既有題材

清單用 `fetch_plan.py --list bosses`，已用題材對照 `參考素材索引.md`。

### Step B3 — 提案

每案給：

- **名稱**（四字為主，如「熾影幻狐」「滄溟晶龍」）
- **一句核心意象**
- **配色**（主色 2–3 色＋點綴；說明怎麼跟漁場的藍綠底色拉開）
- **輪廓特徵**：在漁場裡一眼認出牠的招牌部位
- **階段變化**（多階段時）：每階靠什麼升級（追加部件／拿掉部件／換色／加圖騰），見法則第三節
- **包裝**：賣點與一句話宣傳、適合的檔期或定位
- **表演**：被捕獲的反應、彩金表演的媒介與高潮
- **玩法**：彩金玩法的機制、有沒有階段或翻盤、會用到哪些道具
- **設計理由**（2–3 句）：除通則的題材區隔，要寫**外觀的招牌部位怎麼成為表演與玩法的動作來源**、在 Spine 限制下動不動得起來

⚠️ 同一案的外觀、表演、玩法要互相扣住。玩法跟外觀無關（例：九尾狐配老虎機）的提案要重想。

### Step B4 — 產 mini 企劃

照魚類之書的結構，寫**包裝、表演、玩法的概念**與**產圖需要的造型**：格式讀 `references/mini-plan-template.md`。檔名 `企劃_<Boss名>_v1.md`；交出前對照的是**法則第三節**。

### Step B5 — 修訂迴圈

照通則；確認滿意才進 Step 3。

---

## 模式 C：已有規格／提案文件

使用者手上已有自己寫的主題、造型、玩法文件時，**把文件當 mini 企劃**，不再發想。

走模式 C 時讀 `references/mode-c.md`（Step C1 讀文件抽造型條目、Step C2 確認一次），確認後接 Step 3。

## 流程（模式 A：既有企劃）

### Step 1 — 取得企劃

問使用者要做哪一隻；沒指定就跑 `fetch_plan.py --list bosses` 列候選。

```sh
python ~/.claude/skills/art-request-sheet/scripts/fetch_plan.py <page_id> _工作暫存/<Boss名>
```

產出格式（`plan.md`＋`NN_<圖名>.png`）見 `生圖線共用流程.md` 第二節。

### Step 2 — 解析企劃

**先盤點包裝、表演、玩法**：企劃的玩法大綱、流程圖、「3.3 Boss 動態」、彩金表演段落寫到什麼程度。寫得完整就照企劃；有缺漏就列成「企劃缺漏建議」（「3.3 Boss 動態」完不完整，以 `boss-demo/動態描述規範.md` 第六節自查清單判斷），照〈包裝、表演、玩法〉一節跟使用者討論——**不改企劃本身**。

再讀「3.2 Boss 靜態」的各階段造型（概念、配色、臉部、身體、姿勢、尺寸），並**實際 Read 企劃的外觀圖**：

- 企劃圖常混著 UI mockup、漁場背景、佔位角色（熾影幻狐的變身分鏡用的是另一隻狼）——**認清哪張才是定稿外觀**
- 文字與圖不一致時（例：劍魔通緝令），列給使用者，**問要照文字還是照圖**
- 尺寸寫「參考某既有 Boss」時，換算成 16:9 畫面比例；拿不準就用預設 55%

### Step 3 — 組提示詞

Read `prompt模板.md` 第一節，依企劃（或 mini 企劃）填空。**畫風錨點依模板第二節決定**。存到 `_工作暫存/prompt_<Boss名>_<階段>.txt`（UTF-8）。

### Step 4 — 算圖

```sh
python3 ~/.claude/skills/image-studio/scripts/image-studio-client.py draw \
  --count 2 --prompt-file <prompt.txt> --output <_工作暫存/Boss名/階段> [--reference <畫風或上一階定稿>]
```

**不加 `--remove-background`**：交付物就是灰底。

### Step 5 — 放上 16:9 畫布、統一大小

```sh
python ~/.claude/skills/boss-design/scripts/fit_canvas.py <算出的圖> <輸出.png> --height 0.55
```

**模型不照比例畫**（同一份提示詞實測一張 95%、一張 65%），所以大小交給腳本：偵測主體外框 → 縮放到指定的畫面高度佔比（寬度上限 50%）→ 羽化合成到精準 1920×1080 灰底。多階段時每階把 `--height` 加 0.03–0.05。

**要透明 PNG 時**（demo、簡報、cut-in 疊圖要單獨的 Boss）：讀 `references/transparent-png.md`（`--transparent` 用法、參數與限制），交付時灰底版與透明版都給。

腳本出現兩種警告要處理：

- `touches the source frame edge`：主體碰到原圖邊緣，可能被切掉 → 開圖確認，被切就重抽
- `upscaled`：原圖主體太小被放大，細節會糊 → 重抽

### Step 6 — 挑圖

挑圖通則（看完所有候選、三種情況的處置）照 `生圖線共用流程.md` 第五節；提示詞問題回 Step 3 修。逐張對照法則第六節。本 skill 常見的失敗：

- Boss 太大，翅膀或尾巴被邊緣切到 → 重抽；兩張都切到就把比例調低
- 畫了地面、漸層、場景 → 平台異常，重抽
- 用別隻 Boss 當畫風參考時，帶進了那隻的造型元素 → 重抽；反覆發生就改成文字描述畫風

### Step 7 — 多階段接續

前一階定稿後，拿它當 `--reference` 做下一階（模板第一節的多階段段落）。**每一階都要使用者確認**才往下做，不要一次把所有階段算完。

### Step 8 — 檢視與確認外觀

照 `生圖線共用流程.md` 第六節 1–3（開資料夾給使用者看、自己先跑驗收清單並回報、提調整回 Step 3）。

### Step 9 — 表演交給 boss-demo

**本 skill 不畫捕獲表演的示意圖或分鏡。** 動畫太複雜，靜態示意畫不準；流程是：

1. 外觀定案後，用 `boss-demo` 把捕獲／彩金表演做成可調的 demo
2. 在 demo 裡調到定稿
3. 從 demo 截關鍵格組成分鏡圖、寫回企劃（`boss-demo` 步驟 6）；動態與分鏡文字一律照 `boss-demo/動態描述規範.md`

外觀全部定案後，在 Step 10 一起問。

### Step 9.5 — 絕招／技能 cut-in 特寫（選做）

企劃或提案簡報需要「放絕招時的角色特寫」才做；沒要就跳過。要做時讀 `references/cutin.md`（提示詞、算圖、構圖規則、挑圖）。

### Step 10 — 交付與銜接

- 交付通則照 `生圖線共用流程.md` 第六節 4–5；前科回寫落點：`boss設計法則.md` 第七節或 `prompt模板.md`

#### 提案簡報（使用者要做 Boss 提案簡報時）

讀 `references/proposal-deck.md`（固定 10 頁架構、素材來源、pptx 注意事項）。

**使用者確認外觀（所有階段）都定稿後，主動問要不要接著做：**

| 順序 | 下游 | 產出 | Skill |
|---|---|---|---|
| 1 | 背景 | 漁場邊框、表演背景 | `boss-scene` |
| 1 | 表演道具 | 道具等級系列（罐子、幻石…） | `boss-props` |
| 2 | 表演 demo | 捕獲／彩金表演，定稿後截分鏡、寫回企劃 | `boss-demo` |

- 接續通則（全部以定稿為參考圖延伸、等定稿才做、企劃有寫的一次全部派出去產、從零發想的依 mini 企劃列清單拍板後派出）照 `生圖線共用流程.md` 第六節第 6 條；Boss 線的 mini 企劃看〈表演與玩法〉段落
- 背景與道具彼此獨立，可以同時派；**demo 排在後面**，因為它要用到定稿的 Boss、背景與道具（沒有的先用佔位，事後換）

## 維護說明

- 改規格或驗收標準 → `boss設計法則.md`
- 改提示詞 → `prompt模板.md`（流程不用動）
- 新 Boss 上線後更新清單 → `參考素材索引.md`
- 改補邊或透明化邏輯 → `scripts/fit_canvas.py`，改完跑 `python -m pytest scripts/test_fit_canvas.py`（合成圖，不用網路與配額）
