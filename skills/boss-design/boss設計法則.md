# Boss 設計法則

> 規格與驗收的硬規範。`SKILL.md` 管流程，這份管「什麼叫做對」。
> 來源：魚類之書 7 份活動 Boss 企劃（2026-09-30 調研）與 Tim 的製作限制說明。

---

## 一、交付物定義

本 skill 只產**外觀定稿圖**：Boss 本體，一張圖一個階段，**16:9、純灰底**。

**不做**（企劃裡有，但不歸這支）：

- Boss 專屬背景、表演場景 → `boss-scene`
- 登場橫幅、彩金欄、結算欄、ICON、離場提示 → UI，不歸這支
- 捕獲／彩金表演、分鏡圖 → `boss-demo`：先做成 demo 調到定稿，再從 demo 截分鏡（動畫太複雜，靜態示意畫不準）
- Spine 分件、骨架、動畫規格 → 美術與工程的事，**企劃與本 skill 都不寫**

---

## 二、畫面規格

### 尺寸：用 16:9 畫面抓比例

漁場是橫式 16:9，Boss 大小以「佔畫面多少」來抓：

| 項目 | 預設值 |
|---|---|
| 畫布 | 16:9，輸出 1920×1080 |
| 單階 Boss 本體高度 | 約佔畫面高 **50–60%** |
| 本體寬度 | 不超過畫面寬 **50%**（漁場還要留空間給魚群與炮台） |
| 多階段 | 每進一階大 **5–10%**（企劃慣用「比前一階稍大一點」） |
| 位置 | 置中，四周留白，**不可被畫面邊緣切到** |

> 預設值取自熾影幻狐企劃的漁場示意圖（本體約佔畫面高 55%）。企劃寫「參考某既有 Boss」時，照企劃；使用者給比例時，照使用者。

### 背景

**純灰色、無漸層、無地面、無文字、無 UI**。

**16:9 與 Boss 大小都由 `scripts/fit_canvas.py` 保證**，不靠提示詞：模型給的畫布比例不固定，Boss 大小也不照比例畫。腳本偵測主體外框、縮放到指定佔比，再羽化合成到 1920×1080 灰底（灰色取自原圖四角，不會有接縫）。

### 朝向與視角

**朝向不統一**，照企劃或設計自然決定（既有企劃：幻狐朝右、晶龍朝左；劍魔、賽特正面）。企劃沒寫就用半側身。

## 三、外觀設計原則

### 1. 剪影在漁場裡要一眼認出

Boss 出現在滿是魚群、子彈、特效的漁場裡。剪影要大塊、主體輪廓清楚，招牌部位（角、翅、尾、武器）要突出輪廓之外。

### 2. 配色：主色 2–3 色＋金色點綴

既有 Boss 的共通點：高飽和、主色 2–3 色、金色點綴、發光特效多。**主色要跟漁場的藍綠底色拉開**——整隻藍色的 Boss 放進深海漁場會消失。

### 3. 多階段：差異要看得出來，身分不能換

既有企劃的升級手法（照用）：

| 手法 | 實例 |
|---|---|
| 追加部件 | 幻狐 三尾 → 六尾 → 九尾；六尾加金屬裝飾 |
| 拿掉部件 | 劍魔 鎧甲逐階崩落（盾形碎片、斧刃碎片碎裂消失） |
| 換色 | 幻狐 橘紅 → 藍白 |
| 追加發光／圖騰 | 幻狐九尾 額頭新增金色圖騰 |
| 放大 | 每階稍大一點 |

**臉型與姿勢沿用前一階**——這是既有企劃的慣例，也讓美術能沿用同一套骨架。

### 4. 做得出來的造型（設計時就考慮，不寫進企劃）

Boss 是全 2D、用 Spine 做動畫，**複雜動作做不到**。外觀設計時就避開需要大動作才成立的造型：

- 招牌部位要能**靠擺動、晃動、發光**表現，不要依賴轉身才看得到的東西（例如只在背面的圖騰）
- 環繞身體的飾物，設計成**只在前方或兩側**，不要繞到身後
- 光環、法陣這類會轉的東西，畫成**平面正圓**，不要透視橢圓

---

## 四、Spine 限制（表演設計用）

Boss 是全 2D Spine，複雜動作做不到。**這節是 `boss-demo` 設計表演時的依據**——demo 裡做得出不代表美術做得出。

| ❌ 做不到 | ✅ 改成 |
|---|---|
| 整隻轉身、3D 轉向 | 瞬間翻面（左右鏡像） |
| 沿斜線或弧線旋轉衝刺 | 水平位移＋殘影特效 |
| 流暢的跳躍、翻滾 | 蹲 → 特效遮住瞬移 → 落地 |
| 飾物繞到身後的環繞 | 只在前方擺盪 |
| 透視的旋轉光環 | 平面正圓轉動 |
| 跟定稿差很多的新姿勢 | 在定稿姿勢上擺動部位（揚頭、張嘴、揮尾、舉武器） |

**做得到、而且好用的表現**（既有企劃的好寫法）：

- 呼吸起伏、魔光一明一暗（劍魔待機）
- 瞇眼、飛機耳、頭和尾巴下垂（幻狐被捕獲）
- 頭部快速膨脹縮小、觸手配合擺動（墨海被捕獲）
- 換表情臉件（年獸的表情差分）
- 張嘴吼叫、身體維持原本的游動姿勢（晶龍）
- 受擊只做閃色（tint）

---

## 五、既有企劃不改

- **不修改任何既有企劃**。發現的錯字、矛盾、做不到的動作描述，**列給使用者看即可**
- 企劃描述了 Spine 做不到的動作時：列出來，並附第四節的改法建議

已知的企劃問題見 `參考素材索引.md`。

## 六、驗收清單

**外觀定稿圖**
- [ ] 16:9、1920×1080、純灰底，無地面、無文字、無 UI
- [ ] 本體高度約佔畫面 50–60%（或企劃／使用者指定的比例），沒有被邊緣切到
- [ ] 企劃（或 mini 企劃）的造型條目都有畫出來
- [ ] 主色 2–3 色，跟漁場藍綠底色拉得開
- [ ] 多階段：每階大一點、差異看得出來、臉型與姿勢沿用前一階
- [ ] 沒有只在背面才成立的招牌、沒有繞到身後的飾物、會轉的東西是平面正圓
