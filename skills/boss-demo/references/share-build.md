# 分享版打包（步驟 5：要把 demo 傳給別人試玩時）

> 從 `SKILL.md` 步驟 5 拆出。

**分享版打包**（要把 demo 傳給別人試玩時）：

- 新檔名帶**版號＋日期**（例：`<boss名>_demo_v3_20261008.html`），**不覆蓋舊版**——試玩者的回饋要對得回是哪一版
- **頁內也要看得到同一組版號＋日期**：檔名是唯一的命名慣例，但附進企劃或轉傳後讀者只看得到頁面，所以 template 頂部放一個 `BUILD = { version: 'v3', date: '20261008' }`，`<title>`、狀態列（`demo-ui`）與 localStorage key 的版號都從它取；打包時檔名與 `BUILD` 對得上才算打完
- **企劃附檔要不要換**：讀 `demo紀錄.md`（`SKILL.md` 步驟 5）——有企劃頁連結且「企劃上目前附的版本」不是這版（含「未附」）時，打包完**問一句**「企劃附檔是舊版，要換成這版嗎？」。使用者說換 → 交給 `plan-dept14-writer`（第九節第 10 條：demo 附在 1.2 玩法大綱、換檔不留舊檔），boss-demo 不自己動企劃頁；換完把紀錄的「企劃上目前附的版本」改成這版。使用者說不換 → 紀錄照舊，交付訊息註明企劃附的仍是舊版
- 附**試玩說明**（`試玩說明.md`），至少寫：
  1. 怎麼開（雙擊用 Chrome／Edge 開，不需要網路）
  2. 每顆按鈕與面板區塊的用途（捕獲、強制播、指定最終倍數、暫停／下一分鏡／結束、模擬、匯出／匯入設定）
  3. **哪些是暫定值**（預設模板補的、企劃矛盾先照分鏡值的、佔位素材）
  4. 回饋怎麼給：調完按「匯出設定」把 JSON 傳回，或貼「變更區段 Markdown」
- HTML＋試玩說明一起壓成 zip（檔名同樣帶版號＋日期）
