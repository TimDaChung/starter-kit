## 模板本文

把 `【】` 依企劃替換，其餘原樣送出。

```
你是一位遊戲美術設計師。請繪製捕魚機遊戲「翅膀技能」的表演分鏡圖。

參考圖是這套裝的炮台與翅膀組合，各格裡的炮台都要照著它畫。

技能名稱：【企劃 2.3 的技能名】
整體設計：【企劃 2.3.A 的一句話概要】

版面要求：
a. 一張圖分成 【N】 格，排成 【M 列 × K 欄】，格與格之間留出明顯間隔。
   **整張圖的長寬比是 【總比例】**——這是【K】 格寬 × 【M】 格高、每格 16:9 算出來的。
b. **每一格都是 16:9 的橫向畫面**，不是正方形，不要把格子壓扁或拉方。
c. 背景是單一純色的中性灰，各格都一樣。不要畫海底、場景或任何背景細節。
d. 炮台的位置與大小（各格完全相同）：
   - **寬度只佔單格畫面寬的三分之一左右**，不要畫大。高度約佔畫面高的五分之二。
   - **左側要留白**：炮台的左邊緣距離畫面左緣，大約要空出畫面寬度的十分之一。**不要把它推到貼齊畫面左邊緣。**
   - 水平中心大約落在「畫面寬度四分之一再往右一點」的位置。
   - 底部貼齊畫面下緣（下半部可以被畫面邊緣切掉一點）。
e. 除了最後一格的結算框以外，畫面上不要有任何文字、數字或 UI。

各格內容（由左至右、由上至下）：

- 【攻擊格，依企劃 1~3 格】：技能的演出過程。【逐格填入企劃的分鏡描述】
- 【倒數第二格】：攻擊結束，畫面上噴出【企劃寫的數量】團金幣——**一團團堆在一起的金色錢幣**，正朝著左下角的炮台飛過去。**不要畫成布製的錢袋或束口袋**，是散開成團的錢幣。
- 【最後一格】：結算畫面。攻擊特效已經結束，畫面回復平靜。炮台的正上方跳出彩金結算框。
    整組**上下只有兩層，不要做成三層**：

    ● 下層：一個**藍色的圓角矩形數字框**，框裡是白色粗體數字「999,999,999」。

    ● 上層：**一條黃綠色漸層的橫幅**，「【技能名】」直接寫在這條橫幅上面（白色粗體字、帶深色描邊）；
      【翅膀名】的翅膀就在**這條橫幅的正後方**，從橫幅的**左右兩端往外露出翅尖**。
      也就是「翅膀 → 黃綠橫幅 → 技能名文字」由後往前**疊成同一組**。
      ✗ **不要讓黃綠橫幅空著、把文字另外擺在橫幅的上方或下方**——那樣就變成分離的三條了。
      ✗ 翅膀**不要加圓形外框、不要做成獨立的圓形 icon**。
      ✗ 黃綠橫幅**不可以省略**——它是技能名的底板，一定要有。

    ★ 結算框的大小與位置：整組的**左邊界與右邊界，要與下方炮台套裝的左右邊界切齊**，
      也就是整組的寬度**就等於炮台（含兩側翅膀）的寬度**，大約佔單格畫面寬的三分之一。
      把它想成「一塊正正蓋在炮台正上方的招牌，招牌跟炮台一樣寬」。
      **不要畫得比炮台寬**，也**不要擺到畫面正中央**。

★ 攻擊範圍：【依稀有度填入下方對應句子】

★ 主體不可以消失（重要）：各攻擊格裡的【主體物件，例:那把巨大的豎琴虛影】
   **每一格都要保持完整、一眼認得出來的形體**——【列出必須畫出的構造，例:琴的外框、琴柱、琴頭裝飾】。
   可以發光、可以半透明、可以被特效包圍，但**絕對不可以溶解成只剩局部線條或一片光束**。
   爆發格特別容易出這個問題——特效再強，主體本身也要還在。
```

## 攻擊範圍（依稀有度擇一填入）

**史詩級**：

```
★ 攻擊範圍（重要）：這個技能是史詩級，攻擊覆蓋「畫面的左半部」。
   攻擊特效要**填滿整個左半邊**——從畫面的左邊緣一路延伸到畫面正中線，上下也要撐開到接近畫面的上緣與下緣。
   **不要只在炮台正上方畫一小團特效**，那樣範圍太小了。
   畫面的右半部則保持乾淨的灰色背景，完全不要有特效。
   ★ **每一個攻擊格都要這樣撐滿左半邊**，不是只有最後爆發那格。
     起手與蓄力那幾格同樣要把特效鋪到畫面上下緣與正中線。
```

**傳說級**：

```
★ 攻擊範圍（重要）：這個技能是傳說級，攻擊覆蓋「整個畫面」。
   攻擊特效要**填滿整張畫面**——左右兩側、上下都要撐滿，不留大片空白的灰色背景。
   **不要只在炮台正上方畫一小團特效**，那樣範圍太小了。
   ★ **每一個攻擊格都要這樣撐滿整張畫面**，不是只有最後爆發那格。
     起手與蓄力那幾格同樣要把特效鋪到畫面的四個邊緣。
```

## 填寫要點

### 企劃分鏡怎麼分配

企劃的分鏡數常與實際要畫的格數對不上，**以「攻擊＋噴錢＋結算」的結構為準**把內容分配進去：

**要畫的格數 ＝ 攻擊格數 ＋ 2**（噴錢、結算）。攻擊格數看企劃分了幾個演出階段，最多三格。

| 攻擊格 | 總格數 | 排列 | **整張總比例（務必填進 a）** |
|---|---|---|---|
| 1 | 3 | 1 列 × 3 欄 | **48:9** |
| 2 | 4 | 2 列 × 2 欄 | **32:18** |
| 3 | 5 | 2 列 × 3 欄 | **48:18** ＋ 右下留空那句 |

⚠️ **總比例一定要寫進提示詞，不能只寫「每格 16:9」。** 2×2 的情況剛好不寫也會對（兩行兩列各自 16:9 湊起來就是 32:18），
所以 4 格版一直沒出事；**換成 2×3 就會塌**——模型沒有總比例可以錨，只能各格自己猜，格子就被壓成方形。
前科：2026-09-29 樂音流羽 5 格版，格子畫成接近 4:3。

5 格時要另外加一句，否則右下會被塞東西：

```
★ 右下角那一格保持空白——只有純灰色的背景，不要畫任何東西進去。
```

企劃的攻擊階段若超過三段，**合併成三格**（登場與蓄力通常可以併）。

### 企劃漏寫噴錢格時

有些企劃的分鏡從攻擊直接接結算，沒有噴錢那格。**照樣補上**，並**主動告知企劃作者**——噴錢與結算是必做的兩格。

### 濾掉非畫面資訊

企劃的分鏡描述常夾雜實作指示，**不要寫進提示詞**：

- 「炸亮瞬間 client 震動畫面 1 秒」——程式行為，畫不出來
- 「噴 3 個金幣動畫，位置隨機，金幣飛往玩家」——只保留「幾團金幣飛向炮台」的畫面，**數量要留**（那是噴錢格的規格），隨機性與動畫是程式的事
- 「數量依美術設計」——直接省略

只留**看得見的畫面**。

## 本 skill 特有的前科

- **貼邊會連鎖毀掉結算格。** 只寫「炮台在左下角」，模型會把它推到貼齊畫面左緣；這麼一來結算格的彩金框沒有空間展開，也無法與炮台垂直對齊。**必須明寫左側留白約 10% 畫面寬**——這三個問題是同一個根因。

- **攻擊範圍要逐格宣告，只寫一次會被套到高潮格。** 寫「這個技能覆蓋整個畫面」，模型會理解成「爆發那格滿版就好」，起手與蓄力格照樣在右側留大片灰。必須明寫「每一個攻擊格都要撐滿」。前科：2026-09-29 樂音流羽五格版，第 3 格滿版漂亮，第 1、2 格右半空著。

- **攻擊階段之間要給出「看得出來的差異」。** 「起手 → 蓄力 → 爆發」對模型太抽象，寫得不夠具體時它會把前兩格畫成幾乎相同的構圖，等於浪費一格。每一格都要寫出**這格獨有的可見變化**（例：「九條弦由左至右逐一亮起，已亮的閃金芒、未亮的維持暗色」比「琴弦蓄力」有用得多）。前科：2026-09-29 樂音流羽候選圖之一，第 1、2 格難以分辨。

- **主體物件在爆發格會被溶掉，必須逐格宣告「它還要在」。** 特效寫得越強，模型越傾向把主體化成純光效：豎琴會只剩一排琴弦、翅膀會只剩一片光。要在全域加一句「各攻擊格的主體都要保持完整形體」，並**點名必須畫出的構造**（琴的外框、琴柱、琴頭裝飾），光說「保持完整」不夠具體。前科：2026-09-29 樂音流羽第 2、3 格的琴身消失，只剩琴弦。

- **「對齊」兩個字推不動模型，要換成「跟誰切齊」。** 寫「結算框要與下方的炮台垂直對齊」完全無效——模型的預設是把 UI 擺畫面正中，而炮台在左側 27%。**給中心也不夠，要給邊界**：寫成「整組的左右邊界與炮台的左右邊界切齊」，對齊與尺寸就變成同一件事，不會互相打架。中途試過「中心對齊＋寬度佔畫面一半」，結果對齊成立但框本身太大——那個寬度值本身就是錯的。

- **同一個元件的不同面向會互相搶，不只是不同元件之間。** 結算框調了四版：寫「對齊」→ 無效；改「中心＋寬度」→ 對齊成立但太大；改「邊界切齊」→ 尺寸對了但**黃綠底板消失**；最後把「尺寸」與「疊層結構」拆成兩段各自講死，才同時成立。教訓是**一個元件的尺寸、位置、內部結構要分段寫**，混在一句話裡必定顧此失彼。

- **給位置還要給尺度。** 只寫「攻擊範圍是左半部」，模型會理解成「特效放在左半邊」而不是「填滿左半邊」——位置對了但範圍只有 1/4。要補上量化邊界（從左邊緣到正中線、上下撐開）與否定句（不要只畫一小團）。炮台比例也是同一個道理。

- **要模型做「不完整」的構圖，必須明講「不要做成什麼」。** 模型傾向把元素各自裝框、整齊排列：獎圈會被填滿中心、翅膀會被裝進圓形 icon。重疊、留空、切斷這類構圖都得加否定句。

- **加字不一定會排擠既有成果。** 加的若是「同一個規格的量化補充」（把攻擊範圍講得更精確），通常不會動到別處；加的若是「新增一個競爭的要求」（例如硬壓特效配色），才會從畫面品質扣。

- **「各格共用同一個場景、同一座炮台」必須明寫。** 不寫的話模型會讓炮台在各格間位移、變形，甚至消失。這條的地位等同 `cannon-wing` 的階段規則。

- **結算格是唯一允許出現文字的格。** 其他格若不明講「不要文字」，模型會自行加上假的 UI 與標籤。

- **16:9 要寫在每一格上，不能只說整張圖的比例。** 只寫「整張 32:18」，模型容易理解成四個正方形拼起來。

- **`slice.py` 要加 `--equal`。** 分鏡有背景色、沒有透明區域，預設的 alpha 投影法找不到切點；而且背景本身就是內容，不可裁到內容框。
