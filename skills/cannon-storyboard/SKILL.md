# 翅膀技能分鏡 Skill

> **執行角色：美術企劃**——關注分鏡是否忠實還原企劃的表演節奏、炮台是否延續定稿；交付前逐條跑 `分鏡規格.md` 的驗收清單。

**前置條件：炮台翅膀必須已經定稿。** 各格裡的炮台都照定稿畫。上游是 `cannon-wing`。

參考圖取用順序：

1. **首選：`cannon-wing` 產出的 3×3 定稿圖，裁下排的「套裝組合」那格**——乾淨、無標註，而且是炮台與翅膀組合在一起的樣子
2. 退而求其次：企劃頁的示意圖。但那些**多半壓著版位框與「實體翅膀尺寸」之類的標註文字**，裁切時盡量避開，並在提示詞裡明講「參考圖上的文字與色塊是企劃標註，不是設計的一部分，不要畫進去」

依賴：
- `分鏡規格.md` — 版面、版位比例、分鏡結構、驗收
- `prompt模板.md` — 提示詞模板
- **`kit 根目錄/references/image-studio-共用須知.md`** — 產圖層面的問題先查那份

## 全程規則

- **一次生成全部格**，不要分格出圖——各格共用同一座炮台，分開畫必然不一致。
- **整張交付，不切格。**
- **每輪至少算 2 張，候選圖一定要全部看完，並從中挑最好的一張。**
  ⚠️ 不是「找到一張正確的就停」——**兩張可能都正確，但有優劣**。前科：2026-09-29 只看第一張就判定達標，使用者看了第二張，特效動線與構圖明顯更好。
  「符合規格」與「畫得好」是兩件事，規格只是門檻。
- 中間產物進 `_工作暫存/`。

## 兩種模式

| 模式 | 觸發 | 起點 |
|---|---|---|
| **A 既有企劃** | 翅膀企劃已寫好 `2.3 翅膀技能` | Step 1 |
| **B 從零發想** | 企劃還沒寫技能，或使用者要重新想 | Step B1 |

模式 B 拍板後接回 Step 3；Step 3 之後兩模式共用。

## 模式 B：從零發想

**只需要提案攻擊段**——噴錢與結算兩格是固定結構，不必發想。

### Step B1 — 讀設計

讀炮台、翅膀、套裝三份企劃的**造型與特效描述**，抓出可用的視覺元素（主題意象、標誌性物件、配色、特效型態）。

### Step B2 — 提案

提出 **2–3 個方向**讓使用者挑，並明講他可以不選、自己給想法。每案包含：

- **技能名稱**：四字為主，呼應套裝特效名的調性（現行實例：九弦聖詠、虎紋雷霜、桃花幻境）
- **攻擊段的演出**：分 1~3 個階段（起手 → 展開 → 命中），每階段一格。簡單的技能 1 格即可，不必硬湊

發想原則：

- 視覺元素要從炮台翅膀的造型長出來，不要憑空加入無關的東西
- **攻擊範圍受稀有度限制**（史詩＝左半畫面、傳說＝全畫面），發想時就要考慮進去——半畫面的技能不要設計成「橫掃全屏」
- 起手與展開要有因果關係，不是兩個無關的畫面

### Step B3 — 拍板

使用者確認後接 Step 3。若他要調整，重提一次完整的三項（名稱＋兩格），不要只給差異。

## 流程

### Step 1 — 確認上游定稿

確認炮台翅膀已定稿並取得定稿圖。**沒有定稿就先走 `cannon-wing`。**

### Step 2 — 讀企劃

讀翅膀頁的 `2.3 翅膀技能`（走 Notion REST，不走 MCP；作法見 `cannon-wing/SKILL.md` Step 1）。

同時讀**基本資訊表的稀有度**——這決定攻擊範圍是半畫面還是全畫面。

取出各個分鏡的畫面描述後，依下列結構分配：

```
[攻擊 1~3 格] ＋ [噴錢 1 格] ＋ [結算 1 格]  =  3~5 格
```

**要畫的格數 ≠ 企劃的分鏡數。** 企劃分鏡扣掉結算那格就是攻擊段（超過三段要合併），再加噴錢與結算兩格。

⚠️ **有些企劃漏寫噴錢格**（從攻擊直接接結算）。這種情況：

1. **照樣補上噴錢格**——遊戲實際一定會噴錢。
2. **主動告知企劃作者**這份企劃漏了，噴錢與結算是必做的兩格。不要默默補完就算了。

排版與分配方式見 `prompt模板.md` 的「填寫要點」。

### Step 3 — 組提示詞

Read `prompt模板.md` 填空，依稀有度選攻擊範圍的段落。存到 `_工作暫存/prompt_<翅膀名>_分鏡.txt`。

**濾掉企劃裡的非畫面資訊**（「client 震動畫面 1 秒」「數量依美術設計」之類），只留看得見的畫面。

### Step 4 — 算圖

```sh
python3 ~/.claude/skills/image-studio/scripts/image-studio-client.py draw \
  --count 2 --prompt-file <prompt.txt> --reference <炮台翅膀定稿圖> \
  --output <工作暫存/分鏡>
```

**不要加 `--remove-background`**——分鏡是有灰底的完整畫面。

### Step 5 — 挑圖

對照 `分鏡規格.md` 的驗收清單，**候選圖全部看完、挑最好的**。

最常見的偏差：

| 偏差 | 成因 |
|---|---|
| 炮台貼齊畫面左緣 | 只寫「左下角」，要明寫左側留白 10% |
| 炮台畫太大 | 要寫死「寬約佔畫面三分之一」 |
| 特效只有一小團 | 給了位置沒給尺度，要補量化邊界 |
| 特效像貼上去的裝飾 | 缺少「從炮台發出」的動線 |
| 結算框做成三個分離的層 | 要明寫「文字壓在翅膀上、兩者重疊」 |
| 結算框跟著主題變色 | 它是公版 UI，樣式固定 |
| 各格的炮台位移或變形 | 要明寫「各格共用同一座炮台」 |
| 5 格版型的右下空格被塞東西 | 要明寫「那格保持純灰空白」 |
| 只有爆發格滿版，起手／蓄力格留大片灰 | 攻擊範圍要逐格宣告，不能只寫一次 |
| 前兩格攻擊幾乎一模一樣 | 各格缺少「這格獨有的可見變化」 |
| 主體物件在爆發格溶成純光效 | 要逐格宣告「主體保持完整」並點名必須畫出的構造 |
| 結算框沒對到炮台，飄在畫面正中 | 「對齊」無效,要用描述炮台位置的同一句話寫框,並給寬度上限 |
| 格子被壓成方形（2×3 時） | 提示詞漏寫**整張總比例**；只寫「每格 16:9」在 2×2 剛好會對、2×3 必塌 |

### Step 6 — 交付

**整張圖直接交付，不切格。** 檔名帶翅膀名與技能名（例：`春桃枝翼_桃花幻境_分鏡.png`）。開資料夾給使用者看。
