# 寵物進化對照圖 Skill

> **執行角色：美術企劃**——關注兩階的進化是否有設計巧思與背景故事、是否忠實還原企劃；交付前逐條跑驗收清單，不合格就重抽或改提示詞。

依賴同資料夾的檔案：

- `寵物進化設計法則.md` — 進化差異、裝飾、配色、畫風的規範與驗收清單（硬規範）
- `prompt模板.md` — 提示詞模板、參考圖使用規則（改提示詞只改這份）
- `參考素材索引.md` — 既有寵物清單（撞題檢查）、既有企劃位置、試作成品
- `scripts/fetch_plan.py` — 撈寵物清單、讀企劃文字並下載企劃圖

以及 kit 層級的共用參照：

- **`kit 根目錄/references/image-studio-共用須知.md`** — 算圖中斷、憑證到期、平台偶發異常、注意力零和。**遇到產圖層面的問題先查那份**

---

## 這支 skill 的定位

**產出的是給 3D 美術建模的方向稿，不是上線素材。** 重點是造型、階段邏輯、設計巧思正確。

- **稀有度**：目前只做**史詩級（兩階、進化一次）**。傳說級（三階）尚未納入，但設計史詩級時要照法則第六節預留空間
- **不含**：動態（一般／上陣／虛弱）、道具 ICON（下游從本定稿後製，不生圖）、專屬背景、技能圖示——那些是企劃的其他欄位，這支只管寵物本體造型

## 全程規則

- **法則優先**：產圖前後都對照 `寵物進化設計法則.md`，交付前逐條跑第七節驗收清單
- **每輪至少算 2 張**：平台會偶發異常（底座、底色卡、貼紙風），對策是重抽不是改提示詞
- **二階永遠不給舊參考圖；一階要大改時也不給**：參考圖會把造型拉回舊設定。只有一階沿用舊設定時才給一階舊圖（規則見 `prompt模板.md`）
- **裝飾量照企劃走，不刻意減**：判準是「每件都連得回概念」，不是數量
- **中間產物進 `_工作暫存/`**（已 gitignore）；定稿才輸出到使用者指定位置。**未上線的設計圖不進 repo**（kit 是公開 repo）
- **主動點出企劃問題**：用詞不一致、文字與圖不符、兩階差異不足時直接講，不要自行補完後默默帶過

## 兩種模式

| 模式 | 觸發 | 起點 |
|---|---|---|
| **A 既有企劃** | 使用者指定寵物名，或給 Notion 連結 | Step 1 |
| **B 從零發想** | 使用者只給動物或主題方向，或完全沒給 | Step B1 |

模式 B 的 mini 企劃經使用者拍板後，接回 **Step 3**；Step 3 之後兩模式共用。

---

## 模式 B：從零發想

⚠️ **提案與拍板不可跳過。** 沒等使用者拍板就算圖，是這支 skill 誕生時的前科（貓型寵物試作）。

### Step B1 — 收集方向

問使用者三件事，全部可選，沒給就自由發揮：

1. **動物或主題傾向**（例：貓、海洋哺乳類、東方神獸）
2. **寵物類型**（上陣型／尋寶型——影響技能，也影響造型要偏戰鬥還是偏探索）
3. **配色傾向**

### Step B2 — 避開既有題材

**發想前先重撈寵物清單**，對照 `參考素材索引.md` 列出已用題材：

```sh
python ~/.claude/skills/pet-evolution/scripts/fetch_plan.py --list pets
```

另外避開炮台線已有的動物造型（例：貓 → 避開喵公爵、廚神喵喵）。

### Step B3 — 提案

發想 **2–3 個差異明顯**的方向，並**明講可以都不選、直接自己給主題**。每案給：

- **兩階命名**：一階名、二階名
- **動物 × 概念**：一句話（例：漁港野貓 × 劍客）
- **背景故事**：一句話講「牠經歷了什麼、變成了什麼」
- **錨點**（2–3 個）與**伏筆**（一階的種子 → 二階長成什麼）
- **身體上的變化**：頭身比、體型、至少一處解剖結構改變
- **配色**：一階主色 → 二階主色，延續的點綴色
- **二階的呆萌點**
- **設計理由**（2–3 句）：為什麼選這個題材（跟既有寵物的區隔、跟捕魚主題的關係）、進化的大翻轉靠什麼故事撐住。**沒有理由的提案不交**

### Step B4 — 產 mini 企劃

照道具之書 2.2 節的結構，**只寫產圖需要的部分**：

```
【一階：〈一階名〉】
概念：
配色：
描述：
- （頭身比、體型、表情）
- （服裝配件逐項）
- （招牌道具與姿勢）
- （伏筆：種子寫小、寫隱約）

【二階：〈二階名〉】
概念：
配色：（標明主色怎麼轉換、哪些點綴色延續）
描述：
- （頭身比、體型、站姿；明寫「不是人形」）
- （身體結構的改變）
- （伏筆長成的樣子）
- （服裝配件逐項，全部要跟主題有關）
- （招牌道具——明寫是一階哪件道具變成的）
- （呆萌點）
```

存成 `_工作暫存/企劃_<二階名>_v1.md`。**逐條對照法則第二～四節檢查**後才交出。

### Step B5 — 修訂迴圈

使用者提調整 → **重出一整份完整企劃**（版本號 +1），不要只給差異。確認滿意才進 Step 3。產圖後使用者又改設計，記得折回企劃檔。

## 流程（模式 A：既有企劃）

### Step 1 — 取得企劃

問使用者要做哪一隻；沒指定就跑 `fetch_plan.py --list pets` 列候選讓他挑。

```sh
python ~/.claude/skills/pet-evolution/scripts/fetch_plan.py <page_id> _工作暫存/<寵物名>
```

產出 `plan.md`（企劃全文）與 `img_NN.png`（企劃圖，簽名 URL 約 5 分鐘失效，腳本當下就下載）。**企劃圖要實際 Read 來看**——文字與圖常常不一致（例：摩卡企劃寫「叉子」、圖畫的是打蛋器）。

### Step 2 — 企劃體檢

讀 2.2.A（零星＝一階）與 2.2.C（三星＝二階），用法則第二節逐條檢查企劃本身：

| 檢查 | 不足時 |
|---|---|
| 兩階差異夠不夠大（體型、頭身比、主色） | 提出強化建議 |
| 有沒有錨點、伏筆 | 提出可以埋的種子 |
| 有沒有身體上的變化 | 提出解剖結構的改法 |
| 文字與企劃圖一致嗎 | 列出不一致處 |

⚠️ **有 live 企劃時，不得自行改設計**。強化建議要列出來、**取得使用者同意才寫進提示詞**；使用者不同意就照企劃原樣畫。

### Step 3 — 組提示詞

Read `prompt模板.md`，依企劃（或 mini 企劃）填空。**依模板的「參考圖使用規則」決定要不要帶參考圖**。存到 `_工作暫存/prompt_<寵物名>.txt`（UTF-8）。

### Step 4 — 算圖

```sh
python3 ~/.claude/skills/image-studio/scripts/image-studio-client.py draw \
  --count 2 --prompt-file <prompt.txt> --output <_工作暫存/寵物名/r1> [--reference <一階舊圖>]
```

**不加 `--remove-background`**：交付物本來就要灰底。

### Step 5 — 挑圖

**⚠️ 看完所有候選圖，挑最好的一張。** 「符合規格」與「畫得好」是兩件事。

| 情況 | 處置 |
|---|---|
| 有一張以上正確 | 全部看完，挑最好的，不改提示詞 |
| 兩張錯在同一點 | 提示詞或規格的問題，回 Step 3 修 |
| 兩張錯在不同點 | 隨機變異，重抽 |

逐張對照法則第七節。本 skill 常見的失敗：

- 二階只是「同一隻變大、換衣服」→ 差異不足，回 Step 3 加強體型與主色轉換
- 一階被參考圖拉回舊設定 → 拿掉參考圖
- 二階的臉變寫實動物 → 強化呆萌點那一句，不要一直加「畫卡通一點」
- 一階提前長出二階的招牌 → 把種子寫小、寫隱約
- 底座、底色卡、文字 → 平台異常，重抽

### Step 6 — 檢視與調整迴圈

1. 把候選圖複製到使用者看得到的資料夾，用 `explorer.exe` 開給他看
2. **自己先逐條跑驗收清單**，主動回報哪張好、好在哪、還差什麼，不要等使用者挑
3. 使用者提調整 → 改企劃或提示詞回 Step 3

### Step 7 — 交付

定稿圖輸出到使用者指定位置，附上最終提示詞。若這次產出暴露了新的規則或前科，回寫到 `寵物進化設計法則.md`（第八節）或 `prompt模板.md`。

### Step 8 — 主動接續下游

**使用者確認兩階都定稿後，主動問要不要接著做：**

| 下游 | 產出 | Skill |
|---|---|---|
| 動態分鏡 | 一般／上陣／虛弱，**一階二階各一套**，每個動畫一張 3–4 格 | `pet-parts` |
| 技能 ICON | 技能 1、2（含 64px 檢查） | `pet-parts` |
| 道具 ICON | **後製、不生圖**：`pet-parts/scripts/item_icon.py --half left/right` 從並排定稿裁一階／二階各一，碎片版疊角標 | `pet-parts` |
| 專屬背景 | 培育頁／上陣格共用，16:9 滿版 | `pet-parts` |
| 滿星貼圖 | 企劃有才做 | `pet-parts` |

- **全部以這裡的兩階定稿為參考圖延伸**，不重新發想造型——所以一定要等定稿才做
- 先讀企劃盤點：**企劃有寫的一次全部派出去產**，不要一件一件問；只有企劃沒寫到的才逐項詢問
- 從零發想的寵物沒有企劃：依 mini 企劃提出下游清單與內容，使用者拍板後派出

## 維護說明

- 改設計規範或驗收標準 → `寵物進化設計法則.md`
- 改提示詞 → `prompt模板.md`（流程不用動）

- 傳說級（三階）納入時：法則第一節的稀有度表、第六節、提示詞模板都要擴成三階，並先跟使用者確認第三階走類人還是神話化
