# 拆列與描述寫法（四部機台）

實際案例（4 份原表的代表列＋表↔企劃對應）屬機密，放在網芳 `X:\grp.product.pm1\2. 產品改造\一四部企劃範本\kit-assets\art-request-sheet\實際範例-dept4-slot.md`（X 讀不到換 Y:）；讀得到就先讀它校準寫法，讀不到照這份的去識別化範例。下面的範例一律用「XX 機台」代稱。

## 章節對應表

機台企劃的結構：1.玩法簡介 → **2.畫面呈現** → 3.詳細玩法 → **4.說明頁** → 5.數值／其他設定 → 6.監控 → 後台 → 調整紀錄。章節編號各份略有差異（有的監控在 7、後台在 9），以章名為準。

| 企劃 | 美術需求表 | 怎麼搬 |
|---|---|---|
| 2.1 美術需求表 | — | 只是一行連結（通常寫「待補」），不搬；表做好後要不要回填連結，交付時問使用者 |
| 2.2 入口／ICON 起，到動畫需求之前的每一節 | **靜態**分頁 | 每一節＝一個「項目」；節內的編號條列＝「子項目」，一個元件一列 |
| 2.N 動畫需求（表格：項目／演出位置／時機／描述） | **動態**分頁 | 一列對一列搬，見〈動態分頁〉 |
| 2.N 音效需求表 | — | 不搬（給影音） |
| 1.玩法簡介 | 靜態分頁的「風格：」 | 抓盤面大小、橫式／直式、整體風格；不另開列 |
| 3.詳細玩法、5.數值 | 靜態分頁描述 | 補美術要知道的數量與數值：倍率級距、獎圖種類數、預留位數、狀態條件 |
| 4.說明頁 | **說明頁**分頁 | 一頁一列，見〈說明頁分頁〉 |
| （企劃沒有） | **動態命名表** | 只建空表頭，列入缺漏清單 |
| 6 以後（監控、後台、調整紀錄） | — | 不搬 |

靜態分頁的項目順序照企劃第 2 章的順序。

## 靜態分頁：拆成「畫面×元件」

**一列＝一個畫面裡的一個元件**。A 欄「項目」寫畫面，只填在該畫面第一列，下面的列留空（腳本會垂直合併）；B 欄「子項目」寫元件。

| 企劃內容 | 拆法 |
|---|---|
| 入口／ICON | 一個項目，小 icon、大 icon 各一列 |
| 稱號、Loading 頁 | 各一個項目，通常一列 |
| 主介面 | 一個項目；天列、背景、輪播欄、角色、滾輪區／盤面、地列…每個元件一列，子項目照企劃寫法加序號（「A.天列」「B.背景」） |
| 免費轉／特殊狀態介面 | 另開一個項目，只列跟主介面不同的元件；相同的寫「同一般轉」 |
| 獎圖 | 一個項目，**一個 symbol 一列**（含 WILD、SCATTER、每一級倍數獎圖）；同一組共用的描述寫在第一列，其他列描述留空（腳本合併） |
| Dialog | 一個項目，每種 Dialog 一列 |
| 角色、道具物件 | 一個項目，一個角色一列；有多套服裝時一套一列 |

- **企劃示意圖**（`plan_image`）：企劃該節的主示意圖放在項目第一列，整個項目共用一張時下面的列不填（腳本合併）；每列有自己的圖就各自填
- **參考圖**（`refs`）：局部示意、競品、既有機台素材，最多兩張
- **動態**：這個元件在動態分頁有對應的列 → `Y`，否則 `N`；不確定就留空，列進缺漏清單
  - **反向檢查**：畫面看起來應該有動態（Dialog 開關、刷光、閃爍、跑馬燈、數字滾動、按鈕呼吸等），但企劃動畫需求表沒列 → 仍標 `N`（照企劃），不要自己補動態列；**列進缺漏清單**請使用者確認：「XX 看起來應有 YY 動態，動畫需求表沒列，先標 N」
- **重要度**：企劃不寫，**留空**，交付時請使用者填（範例是 1–5，1 最重要，`-` 表示不適用）；不要自己排
- **美術字需求**：畫面上要做成美術字的文字（機台名、Dialog 標題與內文、按鈕文字、倍率數字）照企劃原文列；後台設定、程式顯示的數值不列

## 描述寫法

照範例，分「風格／樣式／規格」三段，沒有的段落省略：

```
風格：XX 風

樣式：
1.以 XX 為主體，搭配 XX 元素
2.需預留空間顯示獎勵金額
    a.子項目縮排 4 個半形空白

規格：
1.與既有橫式機台大小一樣
```

1. **風格**：整台機台的美術風格（每個需要設計的元件都寫一次，美術單看一列也知道）
2. **樣式**：沿用企劃該節的編號條列；企劃寫「同上」「見 3.2」就換成實際內容
3. **規格**：尺寸、版位、預留位數（「金額框預留 14 位數」）、沿用哪個既有機台的元件
4. 要美術沿用既有素材時直接寫「沿用 XX 機台天列」「同原 XX 牌桌」
5. 企劃裡的紅字在表裡也標紅（spec 用 `{…}`）；企劃寫「待補」「後補」照抄並標紅，不要自己填
6. 對應參考圖時寫「見參考圖1」

## 動態分頁：從動畫需求表搬

企劃 2.N 動畫需求表每一列 → 動態分頁一列：

| 企劃欄 | 表欄 | 規則 |
|---|---|---|
| 項目 | 項目＋時機 | 企劃寫成「主體-狀態」（「投手-待機」）時拆開：項目＝主體、時機＝狀態；同一主體連續多列時，項目只填第一列 |
| 時機 | 時機或描述 | 項目沒有狀態可拆時，企劃的時機直接放「時機」欄；已拆出狀態時，企劃的時機寫進描述第一行「時機：…」 |
| 描述 | 描述 | 寫成「動態需求：」＋編號步驟（1.抬腳 2.舉手 3.投球）；企劃用「→」串的動作拆成編號 |
| 演出位置 | — | 不另開欄；位置影響動作方向時寫進描述 |

- 企劃示意圖：動畫需求表通常沒附圖，用靜態分頁同一元件的企劃圖；企劃有示意影片時轉 GIF 放「動態參考」
- 企劃標「Client 看」的列（程式做的演出）照列，描述保留這句並標紅，交付時列進缺漏清單請使用者確認美術要不要出
- 靜態分頁標 `Y` 但動畫需求表沒有的元件，**不要自己編動作**，列進缺漏清單
- **反向**：寫完動態分頁後，回頭掃一次靜態分頁標 `N`（或留空）的元件，畫面看起來應該有動態（Dialog 開關、刷光、閃爍、數字滾動等）但動畫需求表沒列的，維持 `N`、不補動態列，列進缺漏清單請使用者確認要不要補動畫（2026-10-07 E2E：Dialog 開關、刷光沒列在動畫表，被當成沒有動態）

## 說明頁分頁

企劃第 4 章每一頁（4.1、4.2…）一列：繁中標題＝該頁標題、中文＝該頁內文、圖片說明欄放該頁示意圖。標題語言 ID、英文標題、翻譯三欄留空（不是企劃填的）。

**要不要只建表頭，看子節有沒有實際內容，不看章標題**：章標題常常標紅字「(待補)」，但 4.1、4.2…其實都寫好了（2026-10-07 E2E 實例）。判準：

- 有任何子節有內文或示意圖 → 照寫，有內容的子節各一列；章標題的「待補」記一條缺漏「第 4 章標題仍標待補，子節已有內容，請確認是否定稿」
- 某個子節只有標題、內文是「待補」或空白 → 該列照建，中文欄寫「待補」並標紅，列入缺漏
- 第 4 章底下完全沒有子節內容（只有標題或一行「待補」）→ 只建表頭，列入缺漏

## 動態命名表

企劃不寫 spine 檔名、animation name、秒數與 event，**只建空表頭**（spec 寫 `{"tab": "naming", "rows": []}`），交付時列入缺漏清單：「動態命名表待美術／程式填」。不要從動畫需求表推測命名。

## 改版類（只寫變動）

企劃是既有機台的優化或改版（標題有「優化」「調整」、或有調整標記）時：

1. **只列有變動的元件**，沒變的不列；沿用現有素材的寫「沿用現有 XX」
2. **同一元件有強弱等級時，一個等級一列**（例：保留框 輕度／中度／強度、賠付表 輕度／中度／強度），各列寫該等級的差異；只有部分等級有動畫時，動態欄分開標
3. 依遊戲階段變化的元件（按鈕、提示文字）**一個階段一列**，子項目寫階段名，描述寫該階段顯示的完整文字
4. 動態分頁只列新增或改變的動畫

## 版號從哪裡抓

機台企劃沒有一部那張〈目的〉表，一部的抓法用不上。依序：

1. 企劃頁面屬性「上線版本」（`fetch_plan.py` 輸出的 plan.md 開頭幾行；有的企劃有、有的沒有）
2. 企劃內文寫明的版本（例：「副系統（v20.1 測試）」這類只屬於某一節的，不算整份企劃的版本）
3. 都沒有 → 問使用者

檔名格式本身還沒定（見 format-dept4-slot.md〈檔名〉）。

## 常見缺漏（交付時檢查）

- 重要度（企劃不寫，請使用者填）
- 動態命名表整張待填
- 靜態標 Y 但動畫需求表沒有描述的元件
- 反向：畫面看起來應有動態（Dialog 開關、刷光等）但動畫需求表沒列、先標 N 的元件
- 動畫需求表標「Client 看」的列，美術要不要出
- 說明頁「待補」（看子節內容判斷，不看章標題）
- 企劃示意圖上的數字和第 5 章數值不一致
- 版號抓不到、檔名格式未定
