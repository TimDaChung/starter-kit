# 美術需求表格式規格

來源：一部 PM 手做的原表（位置記在網芳 `X:\grp.product.pm1\2. 產品改造\一四部企劃範本\kit-assets\art-request-sheet\實際範例.md`（X 讀不到換 Y:）），`build_sheet.py` 已照這份實作。改格式就改腳本，再回來更新這份。

## 檔名

`v<版號>_<活動名>_<企劃名>`，例：`v20.3_春節集點_Ming.Chen`、`v20.3_排行榜調整_Ming.Chen`。只有一個分頁，統一命名「**美術需求表**」（2026-10-05 定案；`build_sheet.py` 的 requests 會改名）。

## 欄位

| 欄 | 表頭 | 誰填 | 內容 |
|---|---|---|---|
| A | 項目 | 企劃 | 畫面或狀態名稱，水平置中 |
| B | 子項目 | 企劃 | 通常空白（同一畫面要拆子元件時才用） |
| C | 是否有動態 | 企劃 | 下拉選單 O／X，置中 |
| D | 美術設計圖 | **美術** | 一律留空，美術交稿時貼 |
| E | 設計描述 | 企劃 | 編號條列，見 writing-rules-dept1.md |
| F | 美術字 | — | **預設留空**；使用者明講要填才填 |
| G | 參考圖1 | 企劃 | 主要示意圖／動畫參考 |
| H | 參考圖2 | 企劃 | 同畫面的狀態變體 |
| I | 參考圖3 | 企劃 | 第三種狀態（需要時） |

## 樣式

| 部位 | 規格 |
|---|---|
| 全表 A1:I<n> | 字型 Microsoft JhengHei 10pt、自動換行、垂直置中、黑色細框線 |
| 第 1 列表頭 | 粗體、底色 `#E2EFD9`（淺綠）、水平置中 |
| 第 2 列分隔列 | 底色 `#93C47D`（深綠），A2:H2 合併，不填字 |
| 內容列（第 3 列起） | 列高至少 330px，設計描述長的列依行數加高 |
| 欄寬（px） | A 220、B 50、C 75、D 75、E 600、F 140、G/H/I 550 |
| C 欄 | 資料驗證 ONE_OF_LIST「O、X」，嚴格、顯示下拉 |
| 紅字 | `#FF0000`，只標片段不標整格 |

## 紅字用在哪

照企劃原文的紅字走：Notion 裡 `<span color="red">` 的片段，在表裡標紅。通常是：

- 數值（500、5,000、200 名、5.5 列）
- 「後補」
- 企劃特別強調的規則或文案（「不做紅點」、「大獎格朝上」、「轉 10 次列出 10 筆明細」）

企劃的藍字（內部連結、概念強調）不帶進表。

## 參考圖

- 浮在儲存格上方（不是「插入儲存格內」），錨點在該格左上角
- 預先縮到 530×300 內，剛好在欄寬裡（layout 參考圖欄的 `thumb`）；有圖的列高度至少是圖高＋10px（330px 下限已涵蓋）
- 影片轉成 GIF：預設只取前 10 秒、約 6fps、寬 360px、128 色（`file_upload` 單次上限 10 MB）
