# 武具外觀設計圖 Skill

> **執行角色：美術企劃**——關注武具是否一眼看出類型與題材、招牌部位能不能撐起登場動畫、是否忠實還原企劃；交付前逐條跑驗收清單，不合格就重抽或改提示詞。

依賴同資料夾的檔案：

- `武具設計法則.md` — 畫面規格、外觀原則、配色、驗收清單（硬規範）
- `prompt模板.md` — 提示詞模板、畫風錨點與參考圖規則（改提示詞只改這份）
- `參考素材索引.md` — 既有武具清單（撞題檢查）、企劃位置、已知企劃問題

以及跨 skill 共用的腳本與參照：

- 讀企劃：`~/.claude/skills/pet-evolution/scripts/fetch_plan.py`（boss／pet／武具線共用，抓 Notion 頁面文字與圖）
- 補 16:9 灰底：`~/.claude/skills/boss-design/scripts/fit_canvas.py`
- **`kit 根目錄/references/image-studio-共用須知.md`** — 算圖中斷、憑證到期、平台偶發異常、注意力零和。**遇到產圖層面的問題先查那份**

---

## 這支 skill 的定位

**產出的是給 3D 美術建模的方向稿，不是上線素材。** 重點是類型一眼可辨、題材與企劃一致、招牌部位清楚。

- **一把武具一張圖**：武具沒有進化或階段，不像寵物有兩階；升星只改效果數值與登場動畫（3 星金閃），外觀不變
- **稀有度**：企劃目前只有**傳說**一階（UI 框色「藍＞紫＞紅＞彩」是給未來稀有度用的），本 skill 不因稀有度改畫法
- **不含**：武具 ICON、碎片 ICON、登場動畫分鏡、追擊提示——那些是下游 `weapon-parts`；UI（滿版 Dialog、升星畫面）不在這條線

## 全程規則

- **法則優先**：產圖前後都對照 `武具設計法則.md`，交付前逐條跑第五節驗收清單
- **每輪至少算 2 張**：平台會偶發異常（底座、底色卡、貼紙風、憑空多一隻手），對策是重抽不是改提示詞
- **招牌部位先定再畫**：企劃 §2.9 四把的登場動畫都圍繞一個部位（扇面旋轉、麒麟眼電光、盾面展開、雙劍交叉）。提示詞裡招牌部位要單獨點名，畫出來要是視覺焦點——這是下游分鏡的動作來源
- **裝飾量照企劃走，不刻意減**：判準是「每件都連得回題材」（龍劍上的每個飾件都該是龍、雲、水），不是數量
- **參考圖依 `prompt模板.md` 白名單決定**：企劃有 2D 概念圖時只當「造型參考」，不當畫風參考——會把 3D 成品感拉回 2D
- **中間產物進 `_工作暫存/`**（已 gitignore）；定稿才輸出到使用者指定位置。**未上線的設計圖不進 repo**（kit 是公開 repo）
- **主動點出企劃問題**：wid 缺、美術需求與道具敘述對不上、2D／3D 未寫明時直接講，不要自行補完後默默帶過（已知問題見 `參考素材索引.md`）

## 兩種模式

| 模式 | 觸發 | 起點 |
|---|---|---|
| **A 既有企劃** | 使用者指定武具名，或給 Notion 連結 | Step 1 |
| **B 從零發想** | 使用者只給武器類型或題材方向，或完全沒給 | Step B1 |

模式 B 的 mini 道具企劃經使用者拍板後，接回 **Step 3**；Step 3 之後兩模式共用。

---

## 模式 B：從零發想

⚠️ **提案與拍板不可跳過**（寵物線的前科：沒等拍板就算圖）。

### Step B1 — 收集方向

問使用者三件事，全部可選，沒給就自由發揮：

1. **武器類型傾向**（例：長柄、暗器、樂器類法器、防具）
2. **題材傾向**（中國風奇幻是固定畫風錨點；題材可以是神獸、五行、星宿、神話人物的兵器）
3. **配色傾向**（陣營戰 UI 是深棕深藍，武具本身不受限，但要能在深底上跳出來）

### Step B2 — 避開既有題材

對照 `參考素材索引.md`：既有 4 把是**劍（龍）、扇（鳳）、弩（麒麟）、盾（神獸頭）**，類型與神獸都要避開；另避開寵物線與炮台線已用的動物（例：貔貅在寵物線、貓在炮台線）。有 Notion 權限時重讀一次〈武具系統〉§2.7 與 §2.9，確認清單沒過時：

```sh
NOTION_KEY=$(tr -d '\r\n ' < "<四部readonly_token.txt 路徑>") \
  python ~/.claude/skills/pet-evolution/scripts/fetch_plan.py 25ee22985ac9803aa831d54f90bb1910 _工作暫存/武具系統
```

### Step B3 — 提案

發想 **2–3 個差異明顯**的方向，並**明講可以都不選、直接自己給主題**。每案給：

- **武具名**：四字或五字，比照「玄暝雙龍劍」「離火飛鳳扇」的節奏（修飾語＋神獸／意象＋類型）
- **類型 × 題材**：一句話（例：九節鞭 × 玄武）
- **招牌部位**：登場動畫要圍繞它動的那個部位，一句話寫它會怎麼動
- **風格關鍵字**：3–4 個，照企劃美術需求的寫法（例：中國風、龍飾、豪氣浮誇）
- **配色**：主色、次色、點綴色（點綴通常是金）
- **固有效果概念**：一句話（現有唯一範例：雙龍劍「8% 機率以 25% 傷害追擊一次」）
- **設計理由**（2–3 句）：跟既有 4 把的區隔、題材與陣營戰的關係、招牌部位為什麼撐得起 1–2 秒動畫。**沒有理由的提案不交**

### Step B4 — 產 mini 道具企劃

照〈武具系統〉§2.7 道具列表與 §2.9 登場動畫的欄位，**只寫產圖與下游需要的部分**：

```
【武具：〈武具名〉】
WID：（佔位，待企劃分配；格式比照 3300001）
類型：33-武具　子類別：4-傳說　稀有度：傳說
武器類型：
風格關鍵字：
美術需求：
- （單件／一組幾件；一組時寫「顏色不同但主題相同」）
- （招牌部位——大、清楚、放焦點）
- （材質與配色）
- （裝飾逐項，每件都連得回題材）
道具敘述：（一句，對仗或詩句，比照「一劍出，星沉月隕；雙龍鳴，萬軍潰散。」）
固有效果（0 星解鎖）：（概念一句）
隨機屬性方向：（兩條，從企劃 §3.5 的池子挑：攻擊力％／暴擊率／毀滅一擊率／暴擊傷害／毀滅一擊傷害）
登場動畫概念：（一句，招牌部位怎麼動；格式固定「中間出現 → 動作 A → 動作 B → 統一發光」）
```

存成 `_工作暫存/企劃_<武具名>_v1.md`。**逐條對照法則第二～三節檢查**後才交出。

### Step B5 — 修訂迴圈

使用者提調整 → **重出一整份完整企劃**（版本號 +1），不要只給差異。確認滿意才進 Step 3。產圖後使用者又改設計，記得折回企劃檔。

## 流程（模式 A：既有企劃）

### Step 1 — 取得企劃

武具沒有一把一頁的企劃：目前全部寫在〈武具系統〉一頁裡（§2.7 道具列表＝美術需求與道具敘述；§2.9 登場動畫＝各把的動畫概念；§3.5＝效果池）。整頁抓下來再找該把的段落：

```sh
NOTION_KEY=$(tr -d '\r\n ' < "<四部readonly_token.txt 路徑>") \
  python ~/.claude/skills/pet-evolution/scripts/fetch_plan.py 25ee22985ac9803aa831d54f90bb1910 _工作暫存/武具系統
```

產出 `plan.md`（全文）與 `img_NN.png`（企劃圖，簽名 URL 約 5 分鐘失效，腳本當下就下載）。**企劃圖要實際 Read 來看**——§2.7 道具列表上方與 §2.9 每把下方各有一張圖，文字與圖常不一致。未來武具搬回各自道具頁後，改抓該頁的 page id。

### Step 2 — 企劃體檢

用法則第二節逐條檢查企劃本身：

| 檢查 | 不足時 |
|---|---|
| 有沒有明確的招牌部位；能不能做出 §2.9 那種「一個部位動 1–2 秒」的動作 | 從美術需求裡挑一個部位提為招牌，列出建議 |
| 美術需求、道具敘述、登場動畫三段是否講同一把（雙劍 vs 單劍、飛舞 vs 揮砍） | 列出不一致處 |
| 單件還是一組；一組時各件差異寫了沒 | 提出建議 |
| 有沒有 wid、配色、2D／3D 規格 | 列為缺件回報，不自己補 |
| 文字與企劃圖一致嗎 | 列出不一致處 |

⚠️ **有 live 企劃時，不得自行改設計**。強化建議要列出來、**取得使用者同意才寫進提示詞**；使用者不同意就照企劃原樣畫。

### Step 3 — 組提示詞

Read `prompt模板.md`，依企劃（或 mini 企劃）填空。**畫風錨點與參考圖依模板第二、三節決定**。存到 `_工作暫存/prompt_<武具名>.txt`（UTF-8）。

### Step 4 — 算圖、補 16:9

```sh
python3 ~/.claude/skills/image-studio/scripts/image-studio-client.py draw \
  --count 2 --prompt-file <prompt.txt> --output <_工作暫存/武具名/r1> [--reference <造型參考圖>]
```

**不加 `--remove-background`**：交付物本來就要灰底。

模型給的畫布比例不固定，補成精準 1920×1080 灰底交給腳本：

```sh
python ~/.claude/skills/boss-design/scripts/fit_canvas.py <算出的圖> <輸出.png> --height 0.6 --max-width 0.7
```

腳本偵測主體外框 → 縮放到畫面高 60%（寬超過 70% 時再縮）→ 羽化合成到灰底。橫向武具（弩、扇）會被寬度上限卡住，是預期行為。兩種警告要處理：`touches the source frame edge`（主體被切到 → 開圖確認，被切就重抽）、`upscaled`（主體太小被放大 → 重抽）。

### Step 5 — 挑圖

**⚠️ 看完所有候選圖，挑最好的一張。** 「符合規格」與「畫得好」是兩件事。

| 情況 | 處置 |
|---|---|
| 有一張以上正確 | 全部看完，挑最好的，不改提示詞 |
| 兩張錯在同一點 | 提示詞或規格的問題，回 Step 3 修 |
| 兩張錯在不同點 | 隨機變異，重抽 |

逐張對照法則第五節。本 skill 預期的失敗（初版預設，實測後回寫第六節）：

- 畫了握持的手或角色 → 禁止事項句要放在提示詞最後，不要藏在中段
- 一組兩件畫成兩把完全不同的武器 → 加強「顏色不同但主題相同、造型對稱呼應」
- 只畫一把 → 在開頭就寫「一組兩把」，不只寫在細節段
- 招牌部位太小、被裝飾吃掉 → 提示詞把招牌部位拉到第一句描述
- 畫成 2D 描線、貼紙風、有底座或底色卡 → 平台異常，重抽
- 背景畫成場景（戰場、雲海）→ 補「純灰色背景」在畫風段第一句

### Step 6 — 檢視與調整迴圈

1. 把候選圖複製到使用者看得到的資料夾，用 `explorer.exe` 開給他看
2. **自己先逐條跑驗收清單**，主動回報哪張好、好在哪、還差什麼，不要等使用者挑
3. 使用者提調整 → 改企劃或提示詞回 Step 3

### Step 7 — 交付

定稿圖輸出到使用者指定位置，附上最終提示詞。若這次產出暴露了新的規則或前科，回寫到 `武具設計法則.md`（第六節）或 `prompt模板.md`。

### Step 8 — 主動接續下游

**使用者確認定稿後，主動問要不要接著做：**

| 下游 | 產出 | Skill |
|---|---|---|
| 武具 ICON | 正方形縮圖（含 64px 檢查），武具欄與碎片欄用 | `weapon-parts` |
| 碎片 ICON | 不生圖：ICON 左上疊碎片角標，程式做 | `weapon-parts` |
| 登場動畫分鏡 | 一張 2×2 四格：中間出現 → 招牌動作 A → 招牌動作 B → 統一發光 | `weapon-parts` |
| 3 星金閃版分鏡 | 同四格＋金色閃點，閃點路徑依招牌部位 | `weapon-parts` |
| 追擊提示格 | 選做：左武具圖、右「追擊效果觸發」版面示意 | `weapon-parts` |

- **全部以這裡的定稿為參考圖延伸**，不重新發想造型——所以一定要等定稿才做
- 先讀企劃盤點：**企劃有寫的一次全部派出去產**（§2.7 碎片、§2.9 登場動畫都是企劃明寫的），不要一件一件問；追擊提示格只有使用者要才做
- 從零發想的武具沒有企劃：依 mini 企劃提出下游清單與分鏡拆法，使用者拍板後派出

## 維護說明

- 改設計規範或驗收標準 → `武具設計法則.md`
- 改提示詞 → `prompt模板.md`（流程不用動）
- 新增武具後更新撞題清單 → `參考素材索引.md`
- 企劃把三把「暫放」武具搬回各自道具頁、或補了 wid 後：更新 `參考素材索引.md` 的 page id 與已知問題
- 出現傳說以外的稀有度時：法則第一節的稀有度表要補，並先跟使用者確認低稀有度是否要「減料」（少裝飾、無神獸）還是只換框色
