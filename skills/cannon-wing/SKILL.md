# 炮台翅膀套裝示意圖 Skill

> **執行角色：美術企劃**——關注產出是否忠實還原企劃、是否符合現行 6 套參考的風格與精緻度；交付前逐條跑驗收清單，不合格就重抽或改提示詞。

依賴同資料夾的四份檔案：

- `炮台翅膀設計法則.md` — 規格與驗收清單（硬規範）
- `prompt模板.md` — 提示詞模板與分支調整（改提示詞只改這份）
- `參考素材索引.md` — 6 套參考庫索引
- `scripts/slice.py`、`scripts/compose.py`、`scripts/recolor.py` — 切格、合成、特效調色
- 共用：套裝 ICON 後製 `~/.claude/skills/pet-parts/scripts/item_icon.py`（三條生圖線共用，只吃 Pillow）

以及 kit 層級的共用參照：

- **`kit 根目錄/references/生圖線共用流程.md`** — 魚線十支共用的工作流程：前置需求、讀企劃（`fetch_plan.py`）、全程規則、從零發想的提案與拍板、挑圖、檢視與交付、接續下游。本檔只寫炮台翅膀線獨有的差異
- **`kit 根目錄/references/image-studio-共用須知.md`** — 算圖中斷的處置、憑證到期、平台偶發異常、模型固定偏誤、注意力零和。**遇到產圖層面（而非版型層面）的問題先查那份**

---

## 這支 skill 的定位

**產出的是給美術參考的示意圖，不是直接上線的素材。** 美術會依此重做，所以解析度不必對齊參考庫的 4200px，1200–1800px 足夠；重點是**風格、精緻度、階段邏輯正確**。流程為何這樣設計（程式合成下排、lv2 繼承特效）見 `參考素材索引.md` 末節。

---

## 前置需求

照 `kit 根目錄/references/生圖線共用流程.md` 第一節（image-studio 憑證與 401 處置、四部 pm4 憑證由腳本自動取、Notion 一律走 proxy＋REST、Pillow）。本 skill 的差異：Python 套件另需 **numpy**；Notion 讀取範圍：企劃在「**道具之書**」資料庫（四部）。

## 全程規則

- **法則優先**：產圖前後都要對照 `炮台翅膀設計法則.md`，交付前逐條跑第七節驗收清單。
- 共用規則照 `生圖線共用流程.md` 第三節；本線要主動點出的企劃問題：缺造型描述、階段不全、用詞不一致、內部矛盾。
- **下排永遠由程式合成**，不寫進提示詞。

## 兩種模式

| 模式 | 觸發 | 起點 |
|---|---|---|
| **A 既有企劃** | 使用者指定套裝名，或給 Notion 連結 | Step 1 |
| **B 從零發想** | 使用者只給主題方向、或完全沒給 | Step B1 |

模式 B 產出 mini 企劃並經使用者拍板後，接回 **Step 3** 組提示詞；Step 3 之後兩模式共用。

## 模式 B：從零發想

通則（提案與拍板不可跳過、B1 全部可選、B2 重撈清單、B3 2–3 案＋設計理由、B4 mini 企劃存檔與法則檢查、B5 重出整份）照 `生圖線共用流程.md` 第四節；本 skill 的差異如下。

### Step B1 — 收集方向

問使用者三件事：

1. **主題傾向**（例：東方神獸、蒸汽龐克、深海、節慶）
2. **稀有度**（預設傳說；菁英要降低裝飾量、且通常沒有 lv2）
3. **配色傾向**

### Step B2 — 避開既有題材

清單用 `fetch_plan.py --list cannons`、`--list wings`（路徑見 Step 1），撈道具之書的現有**全部**炮台與翅膀。

已用題材涵蓋：西方神聖（豎琴、女神戰車）、東方神獸（白虎、青鸞、靈狐、瑞鹿）、自然（春意、桃緣、翠晶）、天體（日月星輪、星穹、天機墨座）、武器（焰劍、雙劍、聖戟、海蒼之弓）、貓（喵公爵、廚神喵喵）、節慶（年獸）、海洋（雙鯨、寶船、深海魔靈）。

### Step B3 — 提案

每案給：

- **三段命名**：炮台名＋翅膀名＋套裝特效名（現行慣例，缺一不可；命名多為四字，如「靈狐神契＋浮世幻尾＝幻狐靈契」）
- **一句核心意象**
- **配色**（3–4 色）
- **翅膀的形體**（不必是羽翼——現行有九尾、戰馬、鯨魚、蝶翼、藤蔓）
- **設計理由**（2–3 句）：除通則的題材區隔（跟既有**全部**套裝），要寫炮台與翅膀怎麼互相呼應、lv0 → lv2 的升級靠什麼元件長出來

### Step B4 — 產 mini 企劃

照道具之書的結構產出，**只寫產圖需要的部分**，不寫 WID／i18n／包裹那些欄位：

```
【中央軀幹：〈炮台名〉】
概念：
配色：
lv0 造型：
- （4–5 條，逐條具體到可畫）
- （最上方必須有能量輸出口，且是全體最高點）
- （底部要收斂成尖端或底座）
特效（lv1、lv2 共用）：
lv2 造型變化：
- （3–4 條，手法參考設計法則第五節：追加金飾／放大展開／追加新元件／換色）

【兩側展翼式結構：〈翅膀名〉】
概念：
配色：
lv0 造型：
特效（lv1、lv2 共用）：
lv2 造型變化：
```

檔名 `企劃_<套裝名>_v1.md`；交出前對照的是 `炮台翅膀設計法則.md`。

### Step B5 — 修訂迴圈

照通則；確認滿意才進 Step 3。

## 流程（模式 A：既有企劃）

### Step 1 — 取得企劃

問使用者要做哪一組（炮台名＋翅膀名）。沒指定就列出候選讓他挑。

讀單一企劃頁用共用腳本（產出格式見 `生圖線共用流程.md` 第二節）：

```sh
python ~/.claude/skills/art-request-sheet/scripts/fetch_plan.py <page_id> _工作暫存/<套裝名>
```

要列道具之書候選時用同一支腳本（憑證自動取，找不到或過期照 `plan-dept14-writer/references/notion-access.md` §3）：

```sh
python ~/.claude/skills/art-request-sheet/scripts/fetch_plan.py --list cannons   # 或 --list wings
```

每列：大類、稀有度、名稱、page id。要自己下別的 database query（例如加稀有度 filter）就用 `plan-dept14-writer/scripts/notion_rest.py`：`Notion(find_token(dept="四部")).call("POST", "/databases/217e22985ac9817d8a65c6a6ed6a135c/query", {...})`——**不要自己讀 credentials.json、不要用 PowerShell 打 REST**（5.1 的中文 body 會變 `?` 回 400，`dev-` 主機還要繞 proxy，腳本都處理掉了）。表格內容（WID、關聯道具）`fetch_plan.py` 已展開成一列一行。

### Step 2 — 解析企劃、判斷分支

**這一步決定後面所有參數，不要跳過。**

| 判斷 | 看哪裡 | 影響 |
|---|---|---|
| 階段數 | 有沒有「2.2.C 四星造型變化」 | 有＝3 欄；沒有＝2 欄（菁英級常見） |
| 有無翅膀 | 翅膀是否為獨立企劃頁 | 沒有＝單列，`compose.py --no-wing` |
| 稀有度 | 基本資訊表 | 決定精緻度與裝飾量的措辭 |
| 主體類型 | 概念與描述 | 生物 vs 器物，朝向規則不同 |
| 視角 | 企劃通常沒寫，看示意圖或問使用者 | 正面 vs 俯視，寫法差很多 |
| 造型有無文字 | 2.2.A 是否只寫「造型請見圖X」 | 只有圖＝改版型企劃，必須讀示意圖 |

**基礎階段的名稱不統一**：企劃可能寫「零星造型」或「一星造型」，兩者都對應 lv0。

**改版型企劃**（如喵公爵）只列新增項目、造型寫「請見圖X」、動態寫「維持舊版設計」。這種必須讀企劃示意圖，由讀圖反推造型描述（圖檔已由 Step 1 的 `fetch_plan.py` 存成 `NN_<圖名>.png`，直接 Read）。

### Step 3 — 組提示詞

Read `prompt模板.md`，依 Step 2 的判斷填空並套用分支調整。存到 `_工作暫存/prompt_<套裝名>.txt`（UTF-8）。

**企劃描述照抄，但解剖部位要改寫成畫面方位**（見 `prompt模板.md` 的前科說明）。

### Step 4 — 算圖

```sh
python3 ~/.claude/skills/image-studio/scripts/image-studio-client.py draw \
  --count 2 --prompt-file <prompt.txt> --remove-background --output <工作暫存/素材>
```

`--remove-background` 是必要的：背景交給 `compose.py` 鋪，不靠提示詞控制背景色（實測靠提示詞控制不住）。

### Step 5 — 挑圖

挑圖通則（看完所有候選、三種情況的處置）照 `生圖線共用流程.md` 第五節；提示詞問題回 Step 3 修。逐張 Read，對照 `炮台翅膀設計法則.md` 第七節。常見異常：

- 整格被加橢圓／圓形底色卡 → 去背後整塊被保留，**不可用**，重抽
- 貼紙風（白描邊＋投影）、雜訊背景 → 重抽
- lv2 掉了特效 → 檢查提示詞的階段規則那條是否完整
- **特效顏色跑掉（通常是螢光黃綠）→ 不要改提示詞，走 Step 5.5 後製調色**
- 造型或裝飾本身的配色跑出企劃範圍（例如長出企劃沒有的紅色吊墜）→ 後製救不了，重抽

### Step 5.5 — 特效調色（視需要）

模型對粒子特效有強烈的**螢光黃綠偏好**，四組實測全中。**不要回頭在提示詞裡加強調句去壓**——實測那會搶走造型精緻度的注意力，還會讓特效光暈變得又大又不透明，連帶害去背失敗。改用後製：

```sh
python3 ~/.claude/skills/cannon-wing/scripts/recolor.py <素材.png> <素材_調色後.png> \
  --from 55,105 --to 38,52
```

`--from` 是要換掉的色相帶、`--to` 是目標色相帶（單位為度）。預設值是「黃綠 → 金」。

可行的前提是**色相帶不重疊**：特效落在 hue 60–100，金色約 45、藍色在 180 以上，所以主體不會被波及。實測位移 33.9% 的像素，白羽毛、藍寶石、金屬完全沒動到。

⚠️ 目標色不是金色時要自己換算色相帶，並且**一定要開圖確認主體沒被誤傷**。腳本會印出被改動的像素比例，比例異常高（例如超過 50%）就代表色相帶選錯了。

### Step 6 — 切格

```sh
python3 ~/.claude/skills/cannon-wing/scripts/slice.py <素材.png> <工作暫存/tiles> \
  --cols 3 --rows 2
```

單列或 2 欄時加 `--rows 1 --row-names cannon` / `--cols 2 --col-names lv0,lv1`。

腳本會印出每格尺寸與切線來源。若某欄印出 `no blank band`，代表 lv2 的垂墜裝飾跨到下排，切線落在最細的掃描線上——**要開圖確認有沒有截斷或殘留碎片**。

### Step 7 — 合成

```sh
python3 ~/.claude/skills/cannon-wing/scripts/compose.py <tiles> <輸出目錄> "<標題>"
```

翅膀在下層、炮台在上層，兩者中心對齊。翅膀位置偏高時用 `--wing-offset <px>` 往下調。
2 欄加 `--levels lv0,lv1`；無翅膀加 `--no-wing`。

### Step 8 — 檢視與調整迴圈

照 `生圖線共用流程.md` 第六節 1–3（開輸出資料夾給使用者看、自己先跑驗收清單並回報、提調整回 Step 3；改合成參數則回 Step 7）。

### Step 9 — 交付

交付通則照 `生圖線共用流程.md` 第六節 4–5；前科回寫落點：`炮台翅膀設計法則.md` 或 `prompt模板.md`。

### Step 9.5 — 套裝 ICON（後製，不生圖）

**企劃有 ICON 圖位才做，沒有就跳過本步、不出圖**（Tim 2026-10-02）。目前套裝頁 `2.2 套裝組合` 只有文字、沒有 ICON 圖位。

總覽圖定稿後，道具 ICON 直接從定稿裁（Tim 定案 2026-09-30，寵物、武具線同規），不用 image-studio 另生。套裝 ICON 取**左下格（列 3 lv0 的組合）**；總覽圖底部有一列標籤，用 `--grid-bottom 0.06` 先排除：

```sh
python ~/.claude/skills/pet-parts/scripts/item_icon.py <總覽定稿.png> <輸出資料夾> --name <套裝名> \
  --grid 3x3 --cell 3,1 --grid-bottom 0.06 [--badge <角標.png>]
```

產出 `ICON_<套裝名>.png`（512）＋`ICON_<套裝名>_尺寸預覽.png`（256／128／64）；碎片版 `ICON_<套裝名>_fragment.png`（同圖左上疊碎片角標）自動一起出：角標在網芳 `X:\grp.product.pm1\2. 產品改造\一四部企劃範本\kit-assets\fragment_badge.png`（X 讀不到換 Y:），腳本沒給 `--badge` 就自己去讀；讀不到就只出主圖並提示一行。**角標是線上 UI 素材，不進 repo**（kit 是公開 repo）。驗收看 64px 欄：要認得出是哪套（主色＋剪影）。

### Step 10 — 主動接續下游

**使用者確認炮台翅膀定稿後，主動問要不要接著產這兩項：**

| 下游 | 產出 | Skill |
|---|---|---|
| 配件 | 子彈、彈紋（一般／專屬／雷射）、專屬獎圈 | `cannon-parts` |
| 技能分鏡 | 翅膀技能的演出分鏡圖（格數依稀有度） | `cannon-storyboard` |

兩者的風格都衍生自這裡的定稿，所以**一定要等炮台翅膀確認滿意才做**——這就是三支 skill 分開的原因，不要在炮台翅膀還沒定案時先產下游。

詢問時先讀企劃盤點（有企劃的一次全部派出去產、沒寫到的才逐項問）照 `生圖線共用流程.md` 第六節第 6 條。

> 下游取用參考圖時，`cannon-parts` 用上排的炮台 lv0 那格，`cannon-storyboard` 用**下排的套裝組合格**（它要的是炮台與翅膀組合起來的樣子）。
