# batch-image-brief

> **執行角色：美術**——關注描述的可生圖性與風格一致；嚴守本 skill 三條鐵則。

## 三條鐵則（全部來自使用者實際糾正）

1. **只輸出文字，絕不動手生圖**——使用者要拿去 GPT/chat 生，這裡沒有他要的管道。
2. **一律看實際圖，不靠記憶**——先取得圖檔 Read 過再描述；憑印象寫過一次就被打回（「不要用小說裡的說明」）。
3. **主動給定構圖**——多角色/合成圖要直接寫死位置、視線方向、明暗分區、對立關係，不要等使用者追問「你要不要直接定好角色的位置？」。

## 取圖

- **MTG 卡**：Scryfall API，不要用搜尋引擎撈：
  ```bash
  curl -s "https://api.scryfall.com/cards/named?fuzzy=<卡名>"   # 單卡；.image_uris.art_crop 是純卡圖
  curl -s "https://api.scryfall.com/cards/search?q=<查詢>"      # 循環/系列批次
  ```
  下載 `art_crop` 到 scratchpad 再 Read。角色細節與官方設定衝突時（例：阿耶尼沒有盲眼、金色肩甲），以官方設定校正描述，不確定的點標注出來。
- **一般圖片**：使用者給路徑/貼圖直接 Read。

## 描述格式（每張一段）

固定順序：**主體外觀 → 動作姿態 → 構圖鏡頭 → 色彩光影 → 風格質感**。一整段連貫敘述、非 tag 條列。結尾問中文還是英文版（外部工具吃英文較準；已指定就不問）。

多張合成一張時（例：22 張祭祠＋主體居中）：先各自描述，再輸出一段「合成構圖指示」——明確寫每個元素的區位、大小層級、視覺動線。

## 委派判斷（subagent）

- **>5 張 → fan-out**：按循環/系列分組，每 agent 一組，prompt 自包含（卡名清單、Scryfall 取圖指令、上述描述格式、鐵則 2）。本終端彙整統一口徑。
- ≤5 張本終端直接做。

## 分工邊界

- 要「忠實描述這張圖」→ 本 skill。
- 要「中性化、可換角色的風格 prompt」→ 交給 `image-to-prompt`。
- 使用者要求用我這邊生圖 → 接 `imagen` 系列，不在本 skill 範圍。

## 常見錯誤

| 錯誤 | 後果／修法 |
|---|---|
| 靠訓練記憶描述知名角色 | 細節錯（盲眼、配色）。先抓圖 Read |
| 動手呼叫生圖 | 使用者只要文字。輸出描述即止 |
| 構圖留白等使用者補 | 多一輪來回。主動定位置/視線/明暗 |
| 批次逐張序列處理 | 22 張等半天。>5 張 fan-out |
| 描述混入遊戲機制/背景故事 | 生圖工具吃不了。只寫看得見的視覺 |
